A long coding or research session fills the context window with old tool calls. Drop them and the agent forgets what it learned: which files it read, which approaches failed, which facts it confirmed. This recipe replaces the old part of the history with a summary from [ScaleDown Summarize](https://openrouter.ai/scaledown/summarize) and keeps the recent turns word for word, so the agent remembers what it learned in a fraction of the tokens.

Summarize does one job: it reads one block of text and returns a summary. One call over a whole history drops facts, so a long history gets summarized in chunks.

**Goal:** Write a `maybeCompact` function. While the history is under budget, it returns it unchanged. Once it's over, it returns the system prompt, one summary message, and the most recent turns.

**Outcome:** The history stays under budget however many times it's compacted. Facts from the summarized turns can still be recalled afterwards. The kept turns never start with an orphaned tool result, so the next model call isn't rejected, and a failed summarize call leaves the history as it was.

<Tip>
Prerequisites:

- Your existing TypeScript agent loop runs on Node.js 20+ or Bun as an ES module, with `@types/node` or `@types/bun` installed, and keeps its message history in an array you can rewrite between steps.
- You've configured `OPENROUTER_API_KEY` and installed `zod` 4.
</Tip>

## 1. Call Summarize

`summarize` calls the [Responses API](/api_reference/responses/overview) with your instructions as `instructions` and the text as `input`, and returns the plain-text summary from the `message` output item with its `usage`. The instructions tell the model what to keep: the goal, the decisions made and why, the files and commands the agent touched, the approaches that failed, and the facts it confirmed. They also tell it to copy names exactly, such as file paths, table names, and ticket IDs, because our summaries lost many of them otherwise. Longer histories get split into chunks before they reach `summarize`, so each summary stays short and focused.

```typescript lines
import { z } from 'zod';

const SUMMARIZE_MODEL = 'scaledown/summarize';

const COMPACTION_INSTRUCTIONS = `You are compacting an AI agent's working history so it can continue the task.
Keep: the goal, decisions made and why, files and functions touched, commands that worked,
approaches that failed and why, and facts confirmed. Drop pleasantries and raw tool output
unless a specific value is needed later. Quote identifiers verbatim: ticket IDs, file paths, branch names,
table names, commands, environment variables, numbers and names. Use short bullet points.`;

const ResponseSchema = z.object({
  status: z.enum(['completed', 'incomplete', 'in_progress', 'failed', 'cancelled', 'queued']),
  error: z.object({ message: z.string() }).nullable(),
  incomplete_details: z.object({ reason: z.string() }).nullable(),
  output: z.array(
    z.object({
      type: z.string(),
      content: z.array(z.object({ type: z.string(), text: z.string().optional() })).optional(),
    }),
  ),
  usage: z.object({ input_tokens: z.number(), output_tokens: z.number(), cost: z.number() }),
});
type Usage = z.infer<typeof ResponseSchema>['usage'];

async function summarize(text: string): Promise<{ summary: string; usage: Usage }> {
  const res = await fetch('https://openrouter.ai/api/v1/responses', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: SUMMARIZE_MODEL,
      instructions: COMPACTION_INSTRUCTIONS,
      input: text,
    }),
    signal: AbortSignal.timeout(60_000),
  });
  if (!res.ok) {
    throw new Error(`summarize ${res.status}: ${await res.text()}`);
  }
  const body = ResponseSchema.parse(await res.json());
  if (body.status !== 'completed') {
    throw new Error(
      body.error?.message ??
        `summarize ended as ${body.status}${body.incomplete_details?.reason ? `: ${body.incomplete_details.reason}` : ''}`,
    );
  }
  const message = [...body.output].reverse().find((item) => item.type === 'message');
  const summary = message?.content?.find((part) => part.type === 'output_text')?.text;
  if (summary === undefined) {
    throw new Error('summarize returned no output_text');
  }
  return { summary, usage: body.usage };
}
```

<Warning>
Each `summarize` call is one paid request billed to your OpenRouter account at the [scaledown/summarize](https://openrouter.ai/scaledown/summarize) rate. In our run, compacting an 82k-character history took six calls and cost \$0.00087.
</Warning>

## 2. Turn old messages into text

Summarize reads one block of text and rejects tool calls and tool results with a `400`, so turn the old messages into text first. Keep the tool calls and their results, since that's where most of what the agent learned lives. The message type below is the OpenAI chat format; swap in your own.

```typescript lines
type ToolCall = { id: string; function: { name: string; arguments: string } };
type HistoryMessage =
  | { role: 'system' | 'user'; content: string }
  | { role: 'assistant'; content: string | null; tool_calls?: ToolCall[] }
  | { role: 'tool'; tool_call_id: string; content: string };

function renderMessage(message: HistoryMessage): string {
  switch (message.role) {
    case 'system':
    case 'user':
      return `[${message.role}]\n${message.content}`;
    case 'assistant': {
      const calls = (message.tool_calls ?? []).map(
        (call) => `[tool_call ${call.function.name}] ${call.function.arguments}`,
      );
      return [`[assistant]\n${message.content ?? ''}`, ...calls].join('\n');
    }
    case 'tool':
      return `[tool_result ${message.tool_call_id}]\n${message.content}`;
    default:
      return message satisfies never;
  }
}

const renderHistory = (messages: HistoryMessage[]): string => messages.map(renderMessage).join('\n\n');
```

## 3. Summarize in chunks

One call can't hold everything in a long history, so it drops facts. Split the old turns into chunks of about 16k characters (4k to 5k tokens), summarize each chunk, and join the results. Each chunk gets its own summary, and the calls run in parallel.

```typescript lines
/** One call over a long history drops facts, so histories are compacted in windows of 4k to 5k tokens each. */
const CHUNK_CHARS = 16_000;

function historySize(history: HistoryMessage[]): number {
  return history.reduce((total, message) => total + JSON.stringify(message).length, 0);
}

function chunkMessages(messages: HistoryMessage[]): HistoryMessage[][] {
  const chunks: HistoryMessage[][] = [[]];
  for (const message of messages) {
    const current = chunks[chunks.length - 1]!;
    if (current.length > 0 && historySize(current) + JSON.stringify(message).length > CHUNK_CHARS) {
      chunks.push([message]);
    } else {
      current.push(message);
    }
  }
  return chunks;
}

async function summarizeHistory(messages: HistoryMessage[]): Promise<{ summary: string; usage: Usage[] }> {
  const chunks = chunkMessages(messages);
  const results = await Promise.all(chunks.map((chunk) => summarize(renderHistory(chunk))));
  const summary = results
    .map(({ summary }, index) => (chunks.length > 1 ? `Part ${index + 1} of ${chunks.length}:\n${summary}` : summary))
    .join('\n\n');
  return { summary, usage: results.map(({ usage }) => usage) };
}
```

## 4. Compact when the history gets big

`maybeCompact` keeps the system prompt and the last `KEEP_RECENT` turns, and replaces everything in between with one summary message. Three details keep it safe over a long run:

- **Cut between whole turns.** If the kept turns started with a tool result whose tool call had been summarized away, the next model call would be rejected. So `turnBoundary` moves the cut back until the kept turns start with a user or assistant message. If that reaches the first turn, which happens when one assistant turn made more than `KEEP_RECENT` tool calls, it moves forward instead, so that whole batch gets summarized.
- **Carry the summary forward.** On the next compaction, the earlier summary is kept and the new one is added after it. Once the combined summary passes `SUMMARY_MAX_CHARS`, it's summarized again in `FOLD_WINDOW_CHARS` chunks. One call over the whole summary would drop facts the same way one call over the whole history does.
- **Keep the full history if a call fails.** On any error, `maybeCompact` logs it and returns the history unchanged. The run carries on with a bigger context instead of a gap in its memory.

```typescript lines
const KEEP_RECENT = 8;
const COMPACT_AT_CHARS = 50_000;
/** A carried-forward summary is only re-summarized once it grows past this, so facts survive repeated compactions. */
const SUMMARY_MAX_CHARS = 12_000;
/** A fold re-summarizes the carried summary in windows this big, so no single call has to compress all of it. */
const FOLD_WINDOW_CHARS = 4_000;
const SUMMARY_PREFIX = 'Summary of earlier work in this session:\n\n';

/** Splits text on blank lines into windows of about `maxChars`, so a long summary is folded part by part rather than in one lossy call. */
function chunkText(text: string, maxChars: number): string[] {
  const chunks: string[] = [];
  let current = '';
  for (const paragraph of text.split('\n\n')) {
    if (current.length > 0 && current.length + paragraph.length > maxChars) {
      chunks.push(current);
      current = '';
    }
    current = current.length === 0 ? paragraph : `${current}\n\n${paragraph}`;
  }
  return current.length > 0 ? [...chunks, current] : chunks;
}

async function foldSummary(summary: string): Promise<{ summary: string; usage: Usage[] }> {
  const results = await Promise.all(chunkText(summary, FOLD_WINDOW_CHARS).map((part) => summarize(part)));
  return { summary: results.map(({ summary }) => summary).join('\n\n'), usage: results.map(({ usage }) => usage) };
}

/** Moves the cut so `recent` starts on a user or assistant turn, never on an orphaned tool result. Walks back first; if that reaches the first turn, walks forward instead so an oversized tool batch still gets summarized. */
function turnBoundary(messages: HistoryMessage[], cut: number): number {
  let index = cut;
  while (index > 0 && messages[index]?.role === 'tool') {
    index -= 1;
  }
  if (index > 0) {
    return index;
  }
  index = cut;
  while (index < messages.length && messages[index]?.role === 'tool') {
    index += 1;
  }
  return index;
}

function isSummaryMessage(message: HistoryMessage | undefined): message is { role: 'user'; content: string } {
  return message?.role === 'user' && message.content.startsWith(SUMMARY_PREFIX);
}

export async function maybeCompact(history: HistoryMessage[]): Promise<HistoryMessage[]> {
  if (historySize(history) < COMPACT_AT_CHARS || history.length <= KEEP_RECENT + 1) {
    return history;
  }
  const [system, ...rest] = history;
  if (system === undefined || system.role !== 'system') {
    throw new Error('history must start with the system prompt');
  }
  const carried = isSummaryMessage(rest[0]) ? rest[0].content.slice(SUMMARY_PREFIX.length) : undefined;
  const turns = carried === undefined ? rest : rest.slice(1);
  const cut = turnBoundary(turns, turns.length - KEEP_RECENT);
  const old = turns.slice(0, cut);
  const recent = turns.slice(cut);
  if (old.length === 0) {
    return history;
  }
  try {
    const fresh = await summarizeHistory(old);
    let summary = carried === undefined ? fresh.summary : `${carried}\n\n${fresh.summary}`;
    let usage = fresh.usage;
    if (summary.length > SUMMARY_MAX_CHARS) {
      const folded = await foldSummary(summary);
      summary = folded.summary;
      usage = [...usage, ...folded.usage];
    }
    console.log(JSON.stringify({ compacted_messages: old.length, old_chars: historySize(old), carried_chars: carried?.length ?? 0, summary_chars: summary.length, calls: usage.length, cost: usage.reduce((n, u) => n + u.cost, 0), input_tokens: usage.reduce((n, u) => n + u.input_tokens, 0) }));
    return [system, { role: 'user', content: `${SUMMARY_PREFIX}${summary}` }, ...recent];
  } catch (error) {
    console.error('compaction failed, keeping full history', error);
    return history;
  }
}
```

Call it at the start of each loop step. This sketch isn't part of the runnable file below; `agentStep` stands for your own loop body:

```typescript lines
let history: HistoryMessage[] = [{ role: 'system', content: SYSTEM_PROMPT }];
for (let step = 0; step < MAX_STEPS; step++) {
  history = await maybeCompact(history);
  history.push(await agentStep(history));
}
```

Put anything the agent must never lose, like the user's original task and its constraints, in the system prompt. The system prompt is never summarized.

## Worked example

The session below is made up, but it's the one the captured output came from, so you can run it yourself. `syntheticSession` builds a 100-step coding session (202 messages, 86k characters) in which the agent reads one file per step, with ten facts planted along the way to check what survives: a config path, a failed approach, a rate limit, a table name, a ticket ID, a branch name, a test command, the root cause, a reviewer, and an environment variable. Save steps 1 to 4, without the loop sketch, and these two blocks as one file and run it with `bun run compact.ts`.

```typescript expandable lines
const FACTS = {
  config_path: 'config/billing/invoice-clock.yaml',
  failed_approach: 'jest.spyOn',
  rate_limit: '120 req',
  table_name: 'billing_invoice_runs',
  ticket: 'BILL-482',
  branch: 'fix/invoice-clock-injection',
  test_command: 'bun test packages/billing',
  root_cause: 'caches `Date.now()` at import',
  reviewer: '@mara',
  env_var: 'INVOICE_CLOCK',
} as const;

/** The step at which each fact appears: what the agent said and what the tool returned. */
const PLANTED: Record<number, { said: string; result: string }> = {
  7: { said: `The clock settings live in ${FACTS.config_path}. Reading it.`, result: 'clock:\n  source: system\n  timezone: UTC' },
  15: { said: `Trying to mock the clock with ${FACTS.failed_approach}.`, result: `FAIL: the mock has no effect because ${FACTS.root_cause}.` },
  23: { said: 'Checking the provider rate limit in the docs.', result: `Rate limit for the invoice API: ${FACTS.rate_limit}.` },
  31: { said: 'Looking up the table that records invoice runs.', result: `Table: ${FACTS.table_name} (columns: run_id, invoiced_at, status)` },
  44: { said: `Creating branch ${FACTS.branch}.`, result: `Switched to a new branch '${FACTS.branch}'` },
  58: { said: `Injecting the clock through the ${FACTS.env_var} environment variable instead of mocking.`, result: `Updated invoice.ts to read ${FACTS.env_var} when set.` },
  66: { said: `Running ${FACTS.test_command}.`, result: 'bun test v1.4.2\n 42 pass\n 0 fail\nRan 42 tests across 6 files.' },
};

/** A made-up coding session: `steps` assistant turns, each with one tool call and its result. `offset` shifts the step numbers so a later batch continues an earlier one. */
function syntheticSession(steps: number, offset = 0): HistoryMessage[] {
  const history: HistoryMessage[] = [
    { role: 'system', content: 'You are a coding agent working in the openrouter-web monorepo. Use tools to read files and run commands.' },
    { role: 'user', content: `Fix the flaky test in packages/billing/invoice.test.ts. Ticket ${FACTS.ticket}. Reviewer is ${FACTS.reviewer}.` },
  ];
  for (let i = 0; i < steps; i++) {
    const n = i + offset;
    const file = `lib/module-${n}.ts`;
    const planted = PLANTED[n];
    const said = planted?.said ?? `Step ${n}: reading ${file} to understand how the invoice date flows through the code.`;
    const result = planted?.result ?? `export function helper${n}(x: number): number {\n  return x * ${n};\n}\n// ${'lorem ipsum dolor sit amet '.repeat(20)}`;
    const id = `call_${n}`;
    history.push({ role: 'assistant', content: said, tool_calls: [{ id, function: { name: n % 3 === 0 ? 'run_command' : 'read_file', arguments: JSON.stringify({ target: file }) } }] });
    history.push({ role: 'tool', tool_call_id: id, content: result });
  }
  return history;
}
```

We then appended `syntheticSession(80, 200).slice(2)`, 80 more steps, and compacted again, then once more after another 80 (`syntheticSession(80, 400).slice(2)`). The second compaction carried the first summary forward and grew it to 11.8k characters, just under `SUMMARY_MAX_CHARS`. The third crossed the limit, so the carried summary was folded as well: 11 calls instead of 5, and the summary came back at 10.5k to 10.8k characters, since each 4k window returned about 1.7k. Facts after the third compaction: 8 of 10 in one run, 10 of 10 in the other. Folding re-summarizes a summary, which is where facts go missing, so keep the limit as high as your context allows. With `SUMMARY_MAX_CHARS` lowered to `6_000`, the fold ran on both the second and third compaction (8 and 9 calls), the summary stayed between 2.8k and 4.8k characters, and 10 of 10 facts survived in that run, so a fold is a risk, not a certain loss.

## Check your work

- **Shape.** After compaction, the history is your system prompt, then a `user` message starting with `SUMMARY_PREFIX`, then a `user` or `assistant` message, never a `tool` result.
- **Budget.** `historySize` after compaction is well under `COMPACT_AT_CHARS`: 7k against 50k in our run.
- **Memory.** Ask the agent about something that only appears in the summarized turns, like a file it read or an approach that failed. It should answer correctly. Our summaries kept 9 or 10 of the 10 hidden facts, so expect to lose one now and then. Keep anything that must never be lost in your own state, not in the summary.
- **Repeat.** Compact twice more and check which early facts survive. Ours kept 8 to 10 of 10 after the third compaction, the one that folds the summary.
- **Fail safe.** Break the API key. `maybeCompact` logs the error and returns the history unchanged.

## Variations

With different instructions and no chunking, the same `summarize` call can turn a meeting transcript into decisions and open questions, condense a support ticket's history before an agent picks it up, or boil a long email thread down to one paragraph. Once the input is longer than a few thousand tokens, chunk it as in step 3.
