Curated release notes for the Ori CLI, newest version first. If you are new to Ori, start with [Ori Harness](/guides/ori/harness), which covers installing Ori and running your existing agent CLI. [File Writing](/guides/ori/files) explains what Ori puts in your project.

<Update label="0.17.3" description="November 20, 2026" tags={["Breaking","Patch"]} rss={{ title: "Ori 0.17.3", description: "Ori 0.17.3 removes the old agent commands from the CLI." }}>

Ori 0.17.3 removes the old agent commands from the CLI. Rust interns get memory, which learns from conversation and shows in a new What Ori knows section of desktop Settings. Slack gains slash commands, display blocks and private interns. The desktop app opens threads faster and gets a feedback dialog. `ori omp` starts again on Oh My Pi 18.7 and later.

## Breaking changes

- **Old agent commands.** The CLI no longer has the commands of the retired TypeScript agent. The removed commands are `at`, `backup`, `ci`, `code`, `daemon`, `dev`, `features`, `init`, `interns`, `link`, `logs`, `mcp`, `operations`, `pack`, `restore`, `schedules`, `sessions`, `skills`, `start`, `trial`, `tui`, `unlink`, `workflows`, `workspace` and `harness test`. Scripts that call these commands need a change.
- **Bare `ori`.** Running `ori` with no command shows help. Use `ori codex` or another launcher for a coding session.

## Memory

- **Memory on Rust interns.** Memory is on for every Rust intern. The intern saves facts and rules through its `memory` tool. Set `[features.memory] enabled = false` to turn memory off for one intern.
- **Learning from conversation.** Memory learns lasting facts from conversation by default. A grounded correction replaces the fact that it corrects. A rule that a person sets or edits in Settings stays protected from chat changes. Set `ORI_MEMORY_LEARNING = "off"` under `[features.memory.env]` to turn learning off.
- **Full memory.** When memory is full, memory retires the least lasting eligible fact first. Rules and facts from the current session are never retired. When no fact can be retired, memory refuses the new save. A fact that a person saves always counts as most lasting.
- **Seed file.** Memory imports an `import.jsonl` seed file from its data folder one time at startup.
- **Retries.** A retried correction answers with the saved replacement instead of "not found".

## Desktop app

- **What Ori knows.** Settings has a What Ori knows section. You can see, page through and delete what Ori remembers, grouped by category. You can add a rule there and turn each rule on or off. The section shows only for an intern that has memory, and it appears without a restart when memory turns on.
- **Saved memory in replies.** A reply shows the memory that its turn saved, beneath the reply.
- **Memory fixes.** Memory rows and the no-room line stay correct when a request fails. The memory setting stays correct while Settings stays open.
- **Faster thread opens.** A thread opens from its newest history on Rust and TypeScript interns, so a long thread loads much less data. A launch with many threads makes fewer requests.
- **Empty and failed threads.** An empty thread shows only the composer, with no greeting or suggestions. A thread that fails to load shows the reason and a Try again button. Opening a thread from the sidebar no longer changes the selected intern.
- **Stop.** Stop interrupts the current work and cancels inputs that the intern already queued. A Stop that fails shows its error.
- **Feedback.** A Send feedback dialog sends your feedback through your dashboard session.
- **Settings search.** The Settings page has a search filter.
- **Models.** A change to an intern's default model or thinking effort saves at once, with no intern restart. A chat on Default uses the intern's saved model. After a model change for a personal intern, every Settings tab and personal session stays visible.
- **Fixes.** The dock icon and the Ori app menu stay after the menu bar popover or quick ask opens. A thread brief keeps a leading emoji whole.

## Slack

- **Slash commands.** Type `/<intern slug> <command> <input>` to run a feature's command or a skill. The intern posts what you ran and answers in that thread. You can also type a feature's command by its short name everywhere.
- **Display blocks.** An intern can post Slack messages with header, section, divider, context, rich text, markdown, table and actions blocks. Link buttons are allowed. Interactive elements, images and channel pings are refused, and the error names the refused type.
- **Private interns.** When the private-by-default gate is on for its creator, an unshared Rust intern answers only its creator. Other members get a notice that only they can see.
- **Reply style.** The default Slack reply style drops two rules about how to finish a Slack assignment.

## Interns and features

- **Pages.** Rust interns save HTML pages with a built-in artifacts feature. A saved page includes its scripts, styles and fonts from common CDNs. The intern can list and delete its pages.
- **Turn end event.** A feature can register an interceptor for the `ori/turn` event to learn when a thread's turn ends.
- **Registered automations.** A feature can list, pause, resume and invoke the automations that it registers. A thread's token can no longer run an automation that posts into another session.
- **Feature HTTP.** A feature that sets `ori_http = true` gets `ORI_FEATURE_HTTP_PORT` and `ORI_FEATURE_HTTP_TOKEN`.
- **Uploads.** Uploads to a Rust intern stay inside the storage limit when many files arrive at once. A Rust intern clears interrupted uploads when it starts.

## Schedules

- **Approval for chat schedules.** A schedule that a member asks for in chat names that member. The member approves it on the dashboard, and its runs then act as that member.
- **Scheduled runs.** The desktop app shows a Rust intern's automation runs under Scheduled.
- **Grant check.** The vault refuses a schedule grant whose session ID holds a line break.

## CLI and launchers

- **Oh My Pi.** `ori omp` starts on Oh My Pi 18.7 and later instead of exiting with a model kind error. With no `--model`, `ori omp` starts on Oh My Pi's own OpenRouter default, `openai/gpt-5.5`, instead of a retired model.
- **Launch settings.** A managed launch still downloads launch settings when Ori cannot read the harness version.
- **Sign-in status.** `ori auth` reports an OIDC session that is mid-refresh as active.

- **Sign-in.** The desktop app shows sign-in when the saved key is rejected at boot. Members with two-step verification can connect the dashboard. The sign-in screen is simpler, and the telemetry notice shows after sign-in. A `429` during proof signing shows a rate-limit message.
- **Fixes.** The model label is orange only while it says that the model is unavailable. A refused message names the refusal instead of saying the intern could not be reached. A workspace with no interns points you at your other workspaces. Text selection works from the reading-space gutters, and the Made by Ori dock, panel headers and sidebar footer line up. Icons and the sidebar no longer re-render on every update.

## Interns

- **Substrate interns.** New intern can create a Substrate intern. When the `ori-substrate-default` flag is on, new interns run on Substrate by default. You can reach your own Substrate intern through the dashboard.
- **Rust interns.** The desktop app reaches a Rust intern that serves discover, and it gates features on that intern's capabilities. Made by Ori manages a Rust intern's workflows.
- **Creating interns.** The desktop app offers another intern only when you are allowed to create one.
- **Workspace files.** The daemon serves any workspace file at `/api/workspace/download`, and the runtime serves one workspace file at `/v1/workspace/file`.
- **Desktop turns.** A member's chat turn from the desktop app tells the intern that it came from the desktop.

## Schedules and Slack

- **Digest schedules.** A digest schedule reads today's chats and stays quiet on a day with no chats.
- **Run finished DMs.** The daemon sends a member a Slack DM when a run that they left finishes.
- **Reloads.** A feature reload lets schedule runs in flight finish.
- **Routines.** An approved routine stays armed until a re-armed generation takes it over. A schedule trigger while a run is in flight returns HTTP `409`.
- **One-time grants.** The vault verifies one-time schedule grants natively.
- **Google delegation.** A Google Workspace delegation can name teammates instead of the whole intern.

## Built-in harness and launchers

- **Shell safety.** The shell tool refuses recursive scans of the whole filesystem.
- **MCP servers.** Stdio MCP servers reach the network through the vault proxy. The model learns how to reach a stdio MCP server's service.
- **Server tool calls.** Server tool calls show their URL and query.
- **Turn fixes.** A failed reply's interaction is dropped once its turn ended. A turn that stops before its first event releases its claim. Fork-point discovery lists an indivisible message once.
- **Sessions.** Session summaries load from an index that checks file changes, so session lists load faster.
- **Chat TUI.** The terminal title no longer carries control characters.
- **Claude Code.** When the catalog has no Opus, the Default row points at the allowed start model.
- **Codex.** A Codex model list that is not JSON now produces an error that says what came back.
- **Pi.** Pi setup anchors `!` exclusion entries that climb out of the agent folder.
- **Windows.** Ori joins Windows harness bin folders with backslashes.
- **Skills.** Ori recovers when a real folder replaces a skill wrapper link.

## Telemetry

- **Desktop telemetry.** The desktop app exports traces, crashes and renderer failures with no customer data. Every desktop request sends one `Ori-Desktop` user agent.
- **Failure detail.** The daemon logs the runtime operation behind `ORI_RUNTIME_SERVER_FAILED`. A failed schedule fire exports its failure code, stage and upstream status. Daemon client failures keep the credential error and HTTP status.
- **Vault tunnel.** The vault tunnel names its telemetry `ori.command=vault-tunnel`.

## CLI and built-in harness

- **Headless credentials.** Every headless command reads `.ori/start.json` before `.ori/credentials.json`. The code daemon uses the credential that its `ori code` launch picked.
- **Login recovery.** `ori login --with-key` recovers from a missing credential database.
- **Configuration.** Ori no longer reads the home user config as the workspace layer. When a config file denies access, Ori falls back to environment variables and defaults. Machine policy still fails closed.
- **Approvals.** An approval prompt shows every argument in full, and allow always applies only to the exact call. Slack approval sections show `&`, `<` and `>` as typed.
- **Chat TUI.** A slash command whose argument starts on the next line now runs. A clicked file link reveals the file in the file manager instead of opening it.
- **Recall.** The built-in harness recalls only the current session's compacted context, and a fork recalls only what it inherited.
- **Profiles.** The mutating profile commands print a JSON result envelope.
- **Code daemon.** A failed heartbeat no longer ends the connection, so the daemon stays up under an open TUI. Requests to a hung daemon fail fast. IPv6 runtime hosts work in daemon URLs.
- **Other fixes.** Fetching the docs bundle no longer waits out a long `429` retry delay. A backup no longer fails on a dirty nested repository. The state store recovers on the next call after a failed corruption recovery. Ori removes a launch settings cache that does not decode when no policy applies. Reported cache tokens are kept in harness events.

## Hosted interns and webhooks

- **Webhook verification.** The daemon verifies every webhook with no in-flight limit, so a busy daemon no longer refuses GitHub deliveries. A webhook with malformed signature headers is refused before its body is read.
- **Webhook recipes.** A webhook can name a vault scheme or write its own recipe. A recipe can name a public key or a JWT.
- **Reloads.** A reload applies at once, without waiting for the runs in flight.
- **Self-development.** An intern that changes itself plans first and shows the plan with an Approve button. It builds the plan after the click.
- **Slack questions.** Ori refuses a question with an empty choice, an empty prompt or an id too long for Slack.

## Security

- **Project dotenv.** Ori refuses every user-trust key and `ORI_DAEMON_TOKEN` from a project dotenv file, including `ORI_RELEASE_BASE_URL`.
- **Cloned key files.** Ori refuses a workspace key file that came with a cloned repository.
- **Windows launches.** Ori quotes `.cmd` preflight arguments and refuses `cmd.exe` metacharacters. A setup state directory is restricted by ACL on Windows.
- **Claude Code settings.** Workspace Claude Code settings no longer pass proxy, CA or TLS verification variables.
- **Slack credentials.** The vault tunnel mints a Slack turn credential only for the member who acted, and forwards the verified credential to the vault.
- **Skill links.** Skill link updates stay inside the workspace and refuse symlinked `.ori`, `.agents` and `.claude` trees.
- **Telemetry.** Exported log bodies no longer carry customer text.

- **Cross-family model settings retired.** `ORI_CLAUDE_CROSS_FAMILY_MODELS` and `ORI_CODEX_CROSS_FAMILY_MODELS` no longer have an effect from any source. `ori claude` and `ori codex` keep other families' models, and a launch no longer refuses a model for its family. `ori doctor` warns about a key that is still set locally.

## Codex and Claude Code

OpenRouter refuses an unlisted model. A list set in managed preferences or `/etc/ori/config.json` still narrows on the laptop.
- **Codex reads the served list.** Codex fetches its picker from OpenRouter, so Ori writes no local Codex model catalog. The next start through setup removes a catalog line that an older setup wrote, and prints one line saying so. Long Codex sessions now compact before they reach the model's input limit.
- **Claude Code default.** With `ORI_CLAUDE_DEFAULT_MODEL` set, the Default row, the model that setup saves and the model `ori claude` starts on are the first model OpenRouter serves. An empty served list leaves only the default row.
- **Saved Codex logins.** `ori harness setup codex` now hides every saved login in `~/.codex/auth.json`, as `ori codex` already did, so the Codex app can generate images. Setup and `ori doctor codex` say how to use the ChatGPT plan in plain Codex.

- **Vercel fx.** The new `ori fx` launcher starts Vercel's fx coding agent on OpenRouter.

## Desktop app

- **Chats on the local agent.** A desktop chat can run on the local Ori Code agent in a folder you pick. A models mode chats with any model through the same agent.
- **Turn view.** Turns show a one-line live status, narration, diffs, a files panel that tracks changed files across repositories, and branch commits. The "Worked for" time stops when a turn ends.
- **Routines.** The desktop app manages routines natively, including one-off routines, routines made by describing them, and routine cards in chat. A missed one-off says that it did not run, and you edit it from its due time.
- **Interns.** The desktop app manages an intern's features, secrets, sharing, connections, library and change history. It asks before it suspends an intern, and it keeps an intern whose delete failed visible with a retry.
- **Dashboard and accounts.** The desktop app connects the dashboard with Ori's own sign-in in the default browser, and mirrors the dashboard's connections and your accounts.
- **Library and Artifacts.** The Library is now called Artifacts. An artifact opens in a new chat, and HTML files from chat render with a code toggle.
- **Composer and replies.** You can queue and steer messages, quote and comment on parts of a reply, and use Markdown, LaTeX and list continuation in your own messages. Images and files that an intern makes open from its reply.
- **Updates.** The signed macOS app updates itself from the alpha channel. It asks before it downloads an update, shows progress, and offers Install and restart once the update is ready.
- **Debug info.** Help &gt; Export debug info and Settings &gt; About write a debug report zip to Downloads and show it in Finder. The report holds no keys.
- **Fixes.** Header buttons and window dragging work again, Slack mentions show as names, and markdown code blocks no longer mark every line.

## Slack

- **Long replies stay in one message.** A long turn keeps its reply in one message past Slack's 10-minute stream limit, past 50 plan cards and after a failed stream append.
- **Lost and deleted messages.** A message posts once when its response is lost, and a reply stream ends quietly when someone deletes its message. A stream call that never connected is sent again.
- **Steering and stopping.** Quick messages in a row leave one steer pickup note. Stopping a thread also drops the messages that wait behind the running turn.
- **Threads.** A model override applies only to the thread it was set in. Ori no longer renames a thread that the intern started, and a muted thread stays muted when its state read fails.
- **Formatting and size.** Messages started in Slack keep their formatting, long answers break on a whole character, and the 100 MiB per-turn attachment limit is gone.

## Hosted interns and schedules

- **Feature commands everywhere.** Slack runs, schedule runs, run now and live-edited fires can use feature commands.
- **Routines.** Interns get a routine tool, the time of the turn, and one routines skill. A missed one-off is recorded instead of re-armed for the next year.
- **Skills.** A skills tab and an add skill action manage skills, and slash commands run skills, also when typed mid-sentence.
- **Reloads.** A busy intern applies feature edits after the runs already in flight finish.
- **Turns survive interruptions.** The built-in harness records each turn, request and tool call, and resumes an interrupted turn from that record.

## Backups and versions

- **Labeled versions.** `ori backup --label "<description>"` saves a backup as the next version, such as `v1` or `v2`, and pushes the label when `origin` exists. `ori backup list` shows each version with its parent, time, creator and description.
- **Restore by version.** `ori restore v2` restores that version and commits it forward. `ori restore` refuses a name that is also a branch or tag with `ORI_CLI_RESTORE_REF_AMBIGUOUS`.
- **Versions on the daemon.** The daemon lists, labels and restores versions over its API. A hosted intern knows its versions and points the person to the Backup section of its settings.
- **Build reviews.** When the owner asks the intern to review how it is built, the intern saves a version first. It then rebuilds itself from a list of what it can do and replays recent real requests. "Go back to version v4" undoes the review.

## CLI and built-in harness

- **Default model.** The built-in Ori harness uses `openrouter/auto` when nothing names a model. `ORI_MODEL` still overrides it.
- **Session history.** On a person's machine, a session stays resumable for 30 days after its last turn instead of 72 hours. `ORI_SESSION_HISTORY_RETENTION_DAYS` changes the window. Deployed interns keep 72 hours.
- **Credit and key errors.** The built-in harness says when you are out of credits and why OpenRouter refused. It names key-limit `402` errors, also mid-stream, and links to the key's page.
- **Windows shell.** Ori finds Git Bash on Windows and reports it in `ori doctor`.
- **Chat TUI.** `/approvals` is user-only, so the model cannot switch itself to self-drive. The session picker shows better names.

## Security

- **Project dotenv.** Ori refuses project dotenv variables that change what child processes load.
- **Repository MCP servers.** A repository HTTP MCP server that sends headers needs trust first.
- **Protected paths.** The built-in harness refuses native writes and edits inside `.ori`, and isolates Linux shell commands from host Unix sockets.
- **Dev host.** `ori dev` refuses a discovered `.ori/dev.json` that names a non-loopback host.

- **Background tasks in guardrailed workspaces.** The catalog no longer holds hidden entries for models that the key cannot use. In a guardrailed workspace, Codex Desktop titles, summaries, and commit messages run on the catalog default instead of failing.
- **Catalog refresh.** While Codex is open, the setup catalog follows the models of your key within about 5 minutes. Codex shows the new list on its next start. The detached refresh now stops after 10 seconds, instead of 30.
- **Setup receipt.** Setup records what it wrote in `$CODEX_HOME/ori-openrouter-receipt.json` and marks its `config.toml` lines with `# ori harness setup`. A failed setup rerun leaves the earlier setup as it was, including the thread index and the transcripts.
- **Inline tables.** Setup now works with an inline `features = { ... }` or `agents = { ... }` table that has other members. Before, it failed with `ORI_CLI_HARNESS_CONFIG_INVALID`.
- **Locked thread index.** Setup and reset open the thread index of Codex again after an `SQLITE_CANTOPEN` error, and they wait out a lock that Codex holds.
- **Unreadable thread index.** When the index stays closed, a setup rerun and `ori doctor codex --fix` still finish. They keep the earlier provider of each thread in `~/.codex/ori-openrouter-state.json`, so a later `ori doctor codex --fix` can move the threads back.
- **Reset keeps its record.** When reset cannot rewrite a transcript, it keeps `~/.codex/ori-openrouter-state.json` and tells you to run `ori doctor codex --fix`. A `threads` table without `rollout_path` stops reset with an error that names the table and the column.
- **Blank lines kept.** Setup and reset keep the trailing blank lines of `config.toml`.
- **Doctor after a moved binary.** When the `ori` binary moved, `ori doctor codex --fix` points the credential helper at the new path. It also reports when an older Ori wrote the setup.
- **OpenAI-hosted plugins.** `ori harness setup codex` now says that OpenAI-hosted plugins need a ChatGPT login and do not work through OpenRouter. Local plugins and skills keep working. At `ORI_TELEMETRY_LEVEL=off`, where setup turns Codex plugins off, it says instead that plugins, local ones included, are off and that skills keep working.

It sets `ENABLE_TOOL_SEARCH=false` for any other model, such as `--model openai/gpt-5.5`. Your own `ENABLE_TOOL_SEARCH` still wins. - **Claude Desktop 3.x and later.** `ori harness setup claude` configures Claude Desktop 3.x. Ori no longer refuses a Claude Desktop version because of its major version. A version newer than the verified one gets a warning, and setup configures it only after it passes the setup contract checks. A failed check still refuses.

Before, setup could pass on any copy that Spotlight found, such as an old backup that you do not run. When the copy macOS opens is too old and another copy is in range, setup skips Claude Desktop and names both paths.

A 401 or 403 without the error body of OpenRouter prints a proxy warning, and the launch continues.

- **`ori prime-agent` startup.** The startup model request now stops after 3 seconds. On a timeout or a failure, `ori prime-agent` keeps its built-in model list and prints the existing warning.
- **Windows project folders.** On Windows, a project folder is free again as soon as Codex or Claude Code exits.
- **Temporary folders.** A harness settings preflight that times out no longer leaves an `ori-harness-isolated-*` folder in the temp directory.

## Administrator controls

- **Native harness settings.** Administrators can now set native Claude Code, Codex, and Pi settings as `claude.<key>`, `codex.<key>`, and `pi.<key>`. The values come from launch settings, managed preferences, or `/etc/ori/config.json`. Nothing changes until an administrator sets one, and a JSON value is written as JSON text.
- **Claude Code settings.** Ori offers 141 Claude Code settings. It passes 133 through `--settings` and enforces 8 through `--managed-settings`. The catalog lists 55 more as unavailable, with the reason.
- **Codex settings.** Ori offers 67 Codex settings, and the catalog lists 37 more and every `requirements.toml` key as unavailable. When Codex refuses a value, Ori launches without it and prints one line that names the setting.
- **Pi settings.** Under workspace Pi settings, `ori pi` starts on an overlay agent folder under `~/.ori/pi/agent-overlays/`. Its `settings.json` holds your values with the workspace values on top. Ori saves your own changes back into your `settings.json`.

- **Pi value rules.** Ori checks Pi values against the Pi 1.2.0 settings schema. For example, `pi.httpIdleTimeoutMs` accepts `"disabled"` and refuses `-1`.
- **One model family.** With `ORI_CLAUDE_CROSS_FAMILY_MODELS` off, `ori claude` runs only `anthropic/*` models and refuses any other model before Claude Code starts. With `ORI_CODEX_CROSS_FAMILY_MODELS` off, `ori codex` runs only `openai/*` models. The `/model` lists and the desktop setup catalogs follow the same rule.
- **Codex image generation.** With `ORI_CODEX_IMAGE_GENERATION` off, `ori codex` does not offer image generation, and a caller flag cannot turn it back on. Codex Desktop follows after the next `ori harness setup codex`.
- **Telemetry level.** `ORI_TELEMETRY_LEVEL` takes `full`, `no-content`, or `off`, and defaults to `no-content`. At `off`, Ori exports nothing, every harness starts with `OTEL_SDK_DISABLED=true`, and anonymous product telemetry is off.
- **Workspace collector.** `ORI_TELEMETRY_COLLECTOR` names the collector for Ori and harness telemetry. Only an administrator can set it, so a cloned repository cannot send your prompts to its own collector. `ori doctor` reports the level, the destination, and whether it carries content.
- **Content stays off the laptop collector.** Content never goes to the local `OTEL_EXPORTER_OTLP_ENDPOINT` collector, even at `full`. Ori removes content variables such as `OTEL_LOG_USER_PROMPTS` from every launch that carries no content.
- **Organization minimum version.** `ORI_MINIMUM_VERSION` sets the oldest Ori that the organization allows. Below it, every command except `doctor`, `help`, `update`, and `version` fails with `ORI_CLI_VERSION_BELOW_ORGANIZATION_MINIMUM`. A value in the shell or a user file is ignored.
- **Allowed commands.** `ORI_ENABLED_COMMANDS` lists the top-level commands that may run, for example `login,codex,pi`. Other commands fail with `ORI_CLI_MANAGED_COMMAND_DISABLED`. `help` and `version` always run, and a launcher must also pass `ORI_ENABLED_HARNESSES`. A value in the shell, a user file, or a workspace file is ignored.
- **Update below the minimum.** Below `ORI_MINIMUM_VERSION`, `ori update` runs even when `ORI_ENABLED_COMMANDS` leaves it out.
- **Published minimum notice.** On managed installs, the published-minimum notice now prints before the command, so `ori codex` and `ori claude` show it. Only `ORI_NO_UPDATE_CHECK` hides it. Under `ORI_DISABLE_UPDATES`, the notice tells you to ask IT.
- **Doctor version row.** The Configuration section of `ori doctor` starts with a Version row. It names the running release, the organization minimum, and the published minimum.

## Sign-in and credentials

- **Gateway question.** In an interactive browser sign-in, `ori login` and the sign-in of a harness now ask `Which OpenRouter gateway should Ori sign in through?`, with Global first. When you choose US, Ori exchanges and checks the key on `us.openrouter.ai` and saves `region: "us"`.
- **When Ori skips the question.** Ori does not ask when `--region`, a saved region, `ORI_OPENROUTER_REGION`, a trusted `ORI_OPENROUTER_BASE_URL` or `ORI_OPENROUTER_ENDPOINT`, or a managed `ORI_REQUIRED_REGION` decides the gateway. The `ori auth region` picker now lists the configured region first.
- **Remaining budget.** `ori auth` prints a `budget:` line with the amount left, the limit, the scope, and the reset time. `ori auth --json` adds a `budget` object. `ori doctor` shows the same line and warns at 80% used or when the budget is spent.
- **Budget notice at launch.** `ori claude`, `ori codex`, and the other launchers print one line when 80% or more of the budget is used. Ori never refuses a launch for this. When `ORI_HIDDEN_FIELDS` names `creditLimit`, Ori shows no budget anywhere.
- **Spent budget in `ori code`.** A budget refusal in `ori code` fails with `ORI_OPENROUTER_BUDGET_EXHAUSTED`. The message names the scope, the figures, and the reset time, and suggests a free model.
- **One credential store.** Saved API-key logins, OIDC sessions, and MCP grants now live in `~/.ori/auth/credentials.sqlite`. Under `ORI_CREDENTIAL_STORAGE=protected`, the key is the keychain item `dev.openrouter.ori.credentials.v1`. Under `file`, the key is `~/.ori/auth/credentials.key`.
- **Automatic import.** The first command after the upgrade imports the earlier credential layout and removes it. When an administrator chose `file` and the old layout used the keychain, the import refuses with `ORI_CLI_CREDENTIAL_IMPORT_DOWNGRADE_REFUSED` and names `ori auth migrate --yes`.
- **`ori auth migrate`.** This command imports an earlier layout, moves the key into the custody that the policy names, and promotes a plaintext JSON login. A move into `file` custody needs `--yes`.
- **Custody mismatch.** When the policy names one custody and the key is in the other, commands that use a saved credential fail with `ORI_CLI_CREDENTIAL_CUSTODY_MISMATCH`. `OPENROUTER_API_KEY` keeps working.
- **Keys that were readable on disk.** After an import from a plaintext layout, `ori auth` tells you to run `ori login` to replace the key. `ori auth --json` reports `exposedOnDisk: true` until you sign in again.
- **Sign out everywhere.** `ori logout --all` signs out every saved login and OIDC session on the machine and keeps the store. `ori auth reset` now only discards a store that cannot be read, with its key.
- **Storage in status.** `ori auth` and `ori doctor` print one `credential storage:` field that names the provider and who chose it.

## CLI output

- **One output style.** Every command now prints results, notes, warnings, and failures with the same marks: `✔`, `◇`, `⚠`, and `✗`, with a `↳` hint below. Lines wrap at the terminal width under their mark. Piped output does not wrap.
- **Color.** The marks are colored on a terminal. `NO_COLOR=1`, `FORCE_COLOR=0`, and `TERM=dumb` turn color off, and `FORCE_COLOR=1` turns it on.
- **Help.** `ori --help` shows the commands in five groups. Every command page uses one layout with `Usage`, `Arguments`, `Flags`, `Details`, and `Examples`. A bare group, such as `ori workspace`, prints its help and exits 2.
- **Help text.** Launchers read `Launch <product> through OpenRouter`. Ori corrects help that was wrong, and a launcher that cannot translate `--reasoning-effort` says so on its own page.
- **Machine output.** Under `--json`, stdout carries only the envelope, and a failure also prints its `✗` line and hint on stderr. `ori login`, `ori harness setup`, `ori harness reset`, `ori pack`, `ori link`, `ori unlink`, `ori profile`, and `ori alias` now print envelopes in machine mode.
- **When Ori asks.** A prompt opens only in human mode, with stdin and stdout on a terminal and `CI` not set to a true value. Otherwise the command takes its non-interactive path, or fails with `ORI_CLI_TERMINAL_REQUIRED` and names the reason. For example, `CI=1 ori init` no longer opens the name prompt.
- **Confirmations.** A confirmation defaults to the safe answer and names the flag that skips it, such as `--yes`. After Ctrl-C at a confirmation, `Cancelled.` starts on its own line.
- **Sign-in URL on stderr.** `ori login` prints its sign-in URL and code on stderr, so `ori --json login` keeps stdout for the envelope. A non-interactive login no longer offers the prompt to paste a code.
- **Reports and totals.** `ori doctor`, `ori features validate`, `ori features gate`, `ori mcp list`, `ori mcp test`, `ori ci`, and `ori update --check` end with one totals line. `ori harness list` marks a missing launcher with `◇` and its install command, not `✗`.
- **Steps.** `ori init`, `ori pack`, `ori login`, dependency installs, and other waits show each step with its time. `ori init` ends with one summary and the next commands to run.
- **Tables.** `ori sessions`, `ori logs ls`, `ori daemon list`, `ori schedules list`, `ori interns list`, `ori skills list`, `ori features list`, `ori operations`, and `ori profile` print aligned tables. A narrow terminal drops the least important columns first, and IDs are never cut.
- **Runtime lines.** `ori start`, `ori dev`, and `ori logs` print each runtime line as a time, a scope, and a message, such as `14:02:11  ◇ runtime   listening on http://127.0.0.1:53211`. These lines always go to stderr. `ori logs` shows the stored time of each record.
- **Empty states.** A command with nothing to show prints a `◇` line and a hint. For example, `ori logs` prints `◇ No runtime log entries yet`, and `ori sessions` prints `◇ No sessions recorded yet`.
- **Quiet launches.** A bare `ori claude` no longer prints linked sessions before Claude Code starts. Credential conflicts and version refusals print in one shape with product names, such as `OpenCode`, `Oh My Pi`, and `Factory Droid`.
- **Product names in JSON.** `ori harness list --json` now reports the `displayName` values `OpenCode` and `Oh My Pi`, instead of `opencode` and `omp`.
- **Codex app.** Messages, hints, and help pages now call Codex Desktop "the Codex app".
- **Install offer.** When a product is not installed, the launcher asks to run the install command and defaults to no. Without a terminal, it prints one `✗` line with the quickest install command.
- **Setup and reset narration.** `ori harness setup` prints what it routed and what it replaced, and ends with ``↳ Run `ori harness reset <kind>` to undo this.`` `ori harness reset` prints what it put back, or says that there is nothing to reset.
- **Safe text.** Ori replaces control characters, line separators, and bidirectional overrides in printed paths, model IDs, and provider messages with spaces.
- **Wrapped failures.** When one command wraps the failure of another, the envelope `code` is the inner code, and the hint survives.
- **No raw boot logs.** `ori features validate`, `ori harness list`, `ori init`, and `ori update` no longer print raw `ERROR` boot records above their reports. `ori harness list` warns when features failed to load, and its JSON adds `failedFeatures`.
- **Environment flags.** Ori reads `CI` and similar flags the same way everywhere, so `" 0 "` and `" false "` count as unset.
- **New failure code.** `ori init` with no name and no terminal now fails with `ORI_CLI_PROJECT_NAME_MISSING`, instead of `ORI_CLI_WORKSPACE_CREATE_FAILED`.

## Workflows and feature authoring

- **Durable workflows.** A feature can ship workflows in `workflow.ts`, in `workflows/<name>/workflow.ts`, or as a `workflow` export of `feature.ts`. Build them with `defineWorkflow` from `ori`, using `ctx.step`, `ctx.fanout`, `ctx.call`, and `ctx.sleep` with an explicit `key`.
- **`ori workflows`.** `ori workflows` lists the loaded workflows, and `run`, `runs`, `show`, `cancel`, and `resume` manage runs. `show --mermaid` draws a run. `run --wait` exits non-zero with `ORI_CLI_WORKFLOW_RUN_FAILED` or `ORI_CLI_WORKFLOW_RUN_CANCELLED`.
- **Workflow routes.** The daemon serves workflows under `/api/workflows`, and every route needs the daemon credential. With `ORI_WORKFLOW_RESUME_ON_BOOT=off`, the daemon does not resume interrupted runs at boot. `ori skills get workflow` explains authoring.
- **Required connections.** A feature can declare `ori.requires.connections` in `package.json`, such as `["github", "linear"]`. `ori features add` shows each connection as granted, missing, or not checked, and refuses when one is missing. `GET /api/features` includes `requires.connections`.
- **Private routes in the daemon API.** `GET /api/features/<id>/routes/<path>` serves the `private` GET routes of a feature with the daemon credential. Skill scripts read `ORI_DAEMON_TOKEN`, or `~/.ori/daemon/<port>.token` when the variable is unset.
- **Runtime address.** After `ori start --port <port>` binds, the daemon environment holds `ORI_RUNTIME_HOST` and `ORI_RUNTIME_PORT`, so schedule handlers and helpers can read them.
- **In-run spawns at the limit.** A tool that spawns an unparented thread while all 64 run slots are busy now gets a failed child with `ORI_HISTORY_CAPACITY`. A spawn on the session of the tool fails with `ORI_SESSION_RUN_IN_PROGRESS`. Before, both runs never ended.
