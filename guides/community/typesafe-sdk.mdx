## TypeSafe SDK

You can point an existing [TypeSafe](https://docs.typesafe.ai) client at OpenRouter by changing its base URL. System One requests such as Jev evaluations are then billed to your OpenRouter account and routed through OpenRouter's [Decisions API](/api/api-reference/alphadecisions/submit-a-decisions-questions-and-answers-request).

### Base URL

The TypeSafe-compatible API is available at the following base URL:

```text
https://openrouter.ai/api
```

The SDK appends `/v1/systemone` to the base URL, so requests are sent to `https://openrouter.ai/api/v1/systemone`.

### Authentication

Use your [OpenRouter API key](https://openrouter.ai/settings/keys) as the `Authorization: Bearer <token>` header. The SDK sets this header from the `apiKey` option (`api_key` in Python) or the `TYPESAFE_API_KEY` environment variable.

### Migrating an existing client

Change the base URL and the API key. Everything else stays the same.

<CodeGroup>

```typescript title="client.ts" lines
import { TypeSafeClient } from '@typesafe-ai/sdk';

const client = new TypeSafeClient({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: 'https://openrouter.ai/api',
});
```

```python title="client.py" lines
import os

from typesafe_sdk import TypeSafeClient

client = TypeSafeClient(
    api_key=os.environ["OPENROUTER_API_KEY"],
    base_url="https://openrouter.ai/api",
)
```

</CodeGroup>

Both SDKs also read the base URL from the `TYPESAFE_BASE_URL` environment variable, so you can leave the constructor unchanged and set `TYPESAFE_BASE_URL=https://openrouter.ai/api` and `TYPESAFE_API_KEY=<your OpenRouter API key>` instead.

### Evaluating state against questions

<CodeGroup>

```typescript title="triage.ts" lines
const result = await client.systemOne({
  model: 'jev-1.13',
  state: 'I was charged twice for my subscription.',
  questions: {
    refund: { type: 'noul', instructions: 'Is the customer asking for money back?' },
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: { billing: 'Charges and refunds', technical: 'Bugs and outages' },
    },
  },
});

console.log(result.answers.refund); // { type: 'noul', noul: 0.98 }
```

```python title="triage.py" lines
result = client.system_one(
    model="jev-1.13",
    state="I was charged twice for my subscription.",
    questions={
        "refund": {"type": "noul", "instructions": "Is the customer asking for money back?"},
        "department": {
            "type": "choice",
            "instructions": "Which team should handle this?",
            "criteria": {"billing": "Charges and refunds", "technical": "Bugs and outages"},
        },
    },
)

print(result.answers["refund"])
```

</CodeGroup>

### Model IDs

The compatibility endpoint accepts TypeSafe's bare model IDs and maps them onto OpenRouter's `typesafe/` namespace before routing:

- `jev-1.13` is routed as `typesafe/jev-1.13`.
- `jev-latest` is routed as `~typesafe/jev-latest`, OpenRouter's alias for the newest Jev release.
- IDs that already carry an author prefix, such as `typesafe/jev-1.13`, are used as-is.

The `model` field in the response contains the OpenRouter model ID that served the request.

### Supported endpoints

- `POST /api/v1/systemone` evaluates state against typed questions. It accepts the same request body and returns the same response as `POST /api/alpha/decisions`.

The TypeSafe SDK's model listing (`client.models.list()` in JavaScript) calls `GET /api/v1/models`, which is OpenRouter's [Models API](/api/api-reference/models/list-all-models-and-their-properties) and returns OpenRouter's response shape rather than TypeSafe's, so the SDK rejects it. Browse [OpenRouter's TypeSafe models](https://openrouter.ai/typesafe) or call the Models API directly instead.

### Request and response format

The endpoint implements TypeSafe's request and response shapes. Requests require `model`, `state`, and `questions`, and responses contain `model`, `answers`, and `usage`. OpenRouter additionally returns `id`, `provider`, and `usage.cost`, which both SDKs pass through without error.

```bash title="systemone.sh" lines
curl https://openrouter.ai/api/v1/systemone \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "I was charged twice for my subscription.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is the customer asking for money back?"
      }
    }
  }'
```

```json title="Response"
{
  "id": "gen-dec-1789738314-X5e5eKGQdvR9rblyX250",
  "model": "typesafe/jev-1.13-20260917",
  "provider": "TypeSafe",
  "answers": {
    "refund": { "type": "noul", "noul": 0.98 }
  },
  "usage": { "input_tokens": 275, "output_tokens": 20, "cost": 0.00003 }
}
```

### Using the native Decisions API

`POST /api/v1/systemone` is an alias for OpenRouter's native `POST /api/alpha/decisions` endpoint, which remains the canonical route and is what the [OpenRouter SDKs](/client-sdks/overview) call. Use the alias when you want to keep using the TypeSafe SDK, and the [Decisions API](/api/api-reference/alphadecisions/submit-a-decisions-questions-and-answers-request) directly when you want OpenRouter's SDKs, provider routing options, and full model IDs.
