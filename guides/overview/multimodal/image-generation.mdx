| Field | Description |
|---|---|
| `provider_slug` | Use in `provider.options[slug]` to pass provider-specific parameters |
| `provider_tag` | Use to pin requests to a specific provider. `null` when provider-level routing is unavailable |
| `supported_parameters` | The definitive set of parameters *this* endpoint accepts (a subset of the model-level union) |
| `allowed_passthrough_parameters` | Provider-specific keys accepted under `provider.options[provider_slug]` |
| `supports_streaming` | Whether *this* endpoint supports native SSE streaming |
| `pricing` | Billable pricing lines for this endpoint. Each entry has `billable` (e.g. `output_image`, `input_image`, `input_reference`), `unit` (`image`, `megapixel`, or `token`), `cost_usd`, and an optional `variant` tier (e.g. `2k`, `4k` for resolution-tiered pricing) |

### Capability Descriptors

The `supported_parameters` map uses typed descriptors to describe what each request field accepts:

| Type | Shape | Meaning |
|---|---|---|
| `enum` | `{ type: "enum", values: ["1K", "2K", "4K"] }` | Discrete allowlist of accepted string values |
| `range` | `{ type: "range", min: 0, max: 100 }` | Any integer in `[min, max]` is valid |
| `boolean` | `{ type: "boolean" }` | Supported (present) or unsupported (absent) |

An absent key means the parameter is unsupported by that endpoint.

### Free Image Models

`GET /api/v1/images/models` lists a model's free variant as its own entry, with an ID ending in `:free` (for example, `recraft/recraft-v4.1-flash-v2:free`), alongside the paid entry when both exist. To list only the free image models:


## API Usage

<Note>
**Models served only by the Images API require `POST /api/v1/images`**, not `POST /api/v1/chat/completions`. If a request to `/api/v1/chat/completions` fails because an image-only model does not support chat completions, call `POST /api/v1/images` with `model` and `prompt` instead (including the source image in `input_references` when the chosen edit model requires it). All models listed by `GET /api/v1/images/models` support this endpoint.
</Note>

Send a `POST` request to `/api/v1/images` with the model and prompt:

<CodeGroup>

```python title="Python (requests)" lines
import os
import requests
import json

url = "https://openrouter.ai/api/v1/images"
headers = {
    "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
    "Content-Type": "application/json"
}

payload = {
    "model": "bytedance-seed/seedream-4.5",
    "prompt": "a red panda astronaut floating in space, studio lighting",
    "response_format": "url"
}

response = requests.post(url, headers=headers, json=payload)
result = response.json()

for image in result["data"]:
    if image.get("url"):
        # Signed download URL (expires after 24 hours)
        print(f"Generated image: {image['url']}")
    elif image.get("b64_json"):
        # Inline base64 fallback (e.g. ZDR or storage unavailable)
        print(f"Generated image (base64): {image['b64_json'][:50]}...")

```

```go title="Go" lines
import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"log"
	"net/http"
	"os"

func main() {
	payload, _ := json.Marshal(map[string]string{
		"model":           "bytedance-seed/seedream-4.5",
		"prompt":          "a red panda astronaut floating in space, studio lighting",
		"response_format": "url",
	})

	req, err := http.NewRequest("POST", "https://openrouter.ai/api/v1/images", bytes.NewReader(payload))
	if err != nil {
		log.Fatal(err)
	}
	req.Header.Set("Authorization", "Bearer "+os.Getenv("OPENROUTER_API_KEY"))
	req.Header.Set("Content-Type", "application/json")

	res, err := http.DefaultClient.Do(req)
	if err != nil {
		log.Fatal(err)
	}
	defer res.Body.Close()

	if res.StatusCode < 200 || res.StatusCode >= 300 {
		body, _ := io.ReadAll(res.Body)
		log.Fatalf("Request failed (%d): %s", res.StatusCode, body)
	}

	var result struct {
		Data []struct {
			URL     string `json:"url"`
			B64JSON string `json:"b64_json"`
		} `json:"data"`
	}
	if err := json.NewDecoder(res.Body).Decode(&result); err != nil {
		log.Fatal(err)
	}

	for _, image := range result.Data {
		if image.URL != "" {
			// Signed download URL (expires after 24 hours)
			fmt.Printf("Generated image: %s\n", image.URL)
		} else if image.B64JSON != "" {
			// Inline base64 fallback (e.g. ZDR or storage unavailable)
			fmt.Printf("Generated image (base64): %.50s...\n", image.B64JSON)
		}
	}
}
```

### Response Format

Set `response_format` to `url` to receive a signed download URL for each image instead of inline base64 bytes. URLs expire after 24 hours, with the expiry timestamp reported in `expires_at`. The `usage` field reports token counts and cost when available, and `media_type` is present whenever the format is identifiable (including `image/png`) and omitted only when it could not be determined:

```json lines
{
  "created": 1748372400,
  "data": [
    {
      "url": "https://storage.googleapis.com/openrouter-generated-media-us/v1/...",
      "media_type": "image/png"
    }
  ],
  "expires_at": 1748458800,
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 4175,
    "total_tokens": 4175,
    "cost": 0.04
  }
}
```

### Inline Base64

Omit `response_format` (or set it to `b64_json`) to receive base64-encoded image bytes inline instead of a signed URL. Streaming responses and zero-data-retention requests also return `b64_json`.

```json lines
{
  "created": 1748372400,
  "data": [
    {
      "b64_json": "<base64-encoded-image>",
      "media_type": "image/png"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 4175,
    "total_tokens": 4175,
    "cost": 0.04
  }
}
```

For non-PNG outputs (e.g., JPEG, WebP, or SVG from Recraft vector models), `media_type` reflects the actual format:

```json lines
{
  "created": 1748372400,
  "data": [
    {
      "b64_json": "<base64-encoded-image>",
      "media_type": "image/svg+xml"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 4175,
    "total_tokens": 4175,
    "cost": 0.04
  }
}
```

## Image Configuration Options

### Resolution and Aspect Ratio

Control output dimensions with `resolution`, `aspect_ratio`, or the convenience `size` shorthand:

```json lines
{
  "model": "bytedance-seed/seedream-4.5",
  "prompt": "a landscape photo",
  "resolution": "2K",
  "aspect_ratio": "16:9"
}
```

- `resolution`: normalized tier (`512`, `768`, `1K`, `1.5K`, `2K`, `4K`). Concrete pixel dimensions are derived per-provider.
- `aspect_ratio`: normalized ratio. Pass `auto` to let the provider choose. Common values include `1:1`, `16:9`, `9:16`, `4:3`, `3:4`, `3:2`, `2:3`, `4:5`, `5:4`, and extended ratios like `1:2`, `2:1`, `1:4`, `4:1`, `1:8`, `8:1`, `9:21`, `21:9`. Providers clamp to their supported subset. Check the model's `supported_parameters` for accepted values.
- `size`: convenience shorthand. Pass a tier (`"2K"`) or explicit pixels (`"2048x2048"`). A tier size is equivalent to setting `resolution` and combines with `aspect_ratio`. Explicit pixel sizes are provider-dependent: providers that accept them treat the value as authoritative and reject a mismatched `resolution` or `aspect_ratio` alongside it with a 400. xAI and Sourceful V2/V2.5 reject explicit pixel sizes (use `resolution` and `aspect_ratio` there); Sourceful V2.6 supports them within its dimension limits and does not allow combining them with `resolution` or `aspect_ratio`.

Check the model's `supported_parameters` to see which values each endpoint accepts.

### Quality and Output Format

```json lines
{
  "model": "openai/gpt-image-1",
  "prompt": "a product photo",
  "quality": "high",
  "output_format": "png",
  "background": "transparent"
}
```

- `quality` &mdash; `auto`, `low`, `medium`, or `high`. Providers without a quality knob ignore this.
- `output_format` &mdash; `png`, `jpeg`, `webp`, `svg` (vectorization models only), or `gif` (animation-capable models only, e.g. OpenAI gpt-image-2.6). If omitted, the provider's default applies.
- `frame_count` and `frame_duration_ms` &mdash; animation length (2-64 frames; each model accepts its own range and returns its own error for values outside it) and per-frame display time (20-2000 ms) when `output_format` is `gif`. Ignored by models that do not produce animations. OpenAI renders every frame onto one sprite sheet with a fixed pixel budget, so a bare `aspect_ratio` is shaped to the largest frame that fits (for example `1:1` at 9 frames is 928x928); an explicit `size` is forwarded as-is and can be rejected upstream when the sheet does not fit.
- `markup` &mdash; a transparent PNG overlay (same dimensions as the first reference image) that marks where an edit applies. Image-to-image only; honored by models with markup-guided editing (OpenAI gpt-image-2.6).
- `background` &mdash; `auto`, `transparent`, or `opaque`. `transparent` requires an alpha-capable format (png or webp).
- `output_compression` &mdash; 0-100 for webp/jpeg. Ignored for png.

### Image-to-Image (Reference Images)

Pass one or more reference images via `input_references` to edit an existing image or guide a new generation. Each entry uses the `{ "type": "image_url", "image_url": { "url": "..." } }` shape, where `url` is an HTTP(S) URL or a base64 `data:image/...;base64,...` URL (up to 16 entries globally, narrowed per model):

```json lines
{
  "model": "openai/gpt-image-1",
  "prompt": "make this scene look like a watercolor painting",
  "input_references": [
    {
      "type": "image_url",
      "image_url": {
        "url": "https://example.com/photo.jpg"
      }
    }
  ]
}
```

To list all models that accept `input_references` along with each model's allowed `min` and `max` reference count (`min: 1` indicates an edit model that requires at least one source image), filter `GET /api/v1/images/models` by `supported_parameters.input_references`:

```bash lines
curl -s "https://openrouter.ai/api/v1/images/models" | jq '[.data[] | select(.supported_parameters.input_references != null) | {id, input_references: .supported_parameters.input_references}]'
```

<Note>
**No `bbox` placement parameter on `input_references`:** Reference-image entries do not accept bounding-box (`bbox`) coordinates to control where an input image is placed. `ImageGenerationLayerBoundingBox` (`bounding_box`) is a response-only metadata field returned on decomposed output layers, not a request parameter. Describe placement in `prompt`, or pass a transparent PNG overlay via `markup` on models that support it.
</Note>

### Provider Routing

When a model has multiple providers, use the `provider` object to choose which endpoints can serve the request:

```json lines
{
  "model": "google/gemini-2.5-flash-image",
  "prompt": "a red panda astronaut floating in space",
  "provider": {
    "only": ["google-ai-studio"],
    "allow_fallbacks": false
  }
}
```

The Image API supports these routing fields:

- `only` &mdash; allow only the listed provider slugs.
- `order` &mdash; try providers in the listed order.
- `ignore` &mdash; exclude the listed provider slugs.
- `sort` &mdash; sort eligible endpoints by `price`, `throughput`, or `latency`.
- `allow_fallbacks` &mdash; when `false`, stop after the primary provider instead of trying another eligible provider.
- `zdr` &mdash; when `true`, route only to [Zero Data Retention](/guides/features/zdr) endpoints. If no endpoint qualifies, the request fails.
- `data_collection` &mdash; `allow` (default) or `deny`. When `deny`, route only to endpoints that don't train on your data. Those endpoints may still retain prompts; use `zdr` to exclude retention.

Use `provider_tag` from the [per-endpoint records](#per-endpoint-records) as the base provider slug. See [Provider Routing](/guides/routing/provider-selection) for the routing behavior shared across OpenRouter APIs.

### Provider-Specific Options

Pass provider-specific parameters through `provider.options`, keyed by the provider slug from the endpoints API:

```json lines
{
  "model": "black-forest-labs/flux.2-pro",
  "prompt": "a dramatic portrait",
  "provider": {
    "options": {
      "black-forest-labs": {
        "steps": 40,
        "guidance": 3
      }
    }
  }
}
```

The `allowed_passthrough_parameters` field in each endpoint record lists which keys are accepted.

## Streaming Image Generation

Models that support native SSE streaming (`supports_streaming: true` in the discovery API) can return partial images as they're generated:

```json lines
{
  "model": "openai/gpt-image-1",
  "prompt": "a detailed landscape",
  "stream": true
}
```

The response is an SSE stream with three event types:

**Partial image** &mdash; emitted as each partial render becomes available:
```
data: {"type":"image_generation.partial_image","partial_image_index":0,"b64_json":"<base64>"}
```

**Completed** &mdash; emitted when the final image is ready. The `media_type` field is present whenever the format is identifiable:
```
data: {"type":"image_generation.completed","b64_json":"<base64>","media_type":"image/png","created":1748372400,"usage":{"prompt_tokens":16,"completion_tokens":272,"total_tokens":288,"cost":0.011}}
```

For non-PNG outputs (e.g., SVG from Recraft vector models), `media_type` reflects the actual format:
```
data: {"type":"image_generation.completed","b64_json":"<base64>","media_type":"image/svg+xml","created":1748372400,"usage":{"prompt_tokens":16,"completion_tokens":272,"total_tokens":288,"cost":0.011}}
```

The `usage` object in the completed event includes `cost` (USD), matching the buffered response shape.

**Error** &mdash; emitted if generation fails mid-stream:
```
data: {"type":"error","error":{"message":"Generation failed","code":"server_error"}}
```

The stream terminates with `data: [DONE]`.

<CodeGroup>

```python title="Python (requests)" expandable lines
import os
import sys
import json
import requests

url = "https://openrouter.ai/api/v1/images"
headers = {
    "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
    "Content-Type": "application/json"
}

response = requests.post(url, headers=headers, json={
    "model": "bytedance-seed/seedream-4.5",
    "prompt": "a detailed landscape painting",
    "stream": True
}, stream=True)

if not response.ok:
    raise SystemExit(f"Request failed ({response.status_code}): {response.text}")

raw_lines = []
event_count = 0
failed = False

# iter_lines buffers partial lines, so large base64 events arrive whole
for raw in response.iter_lines():
    if not raw:
        continue
    line = raw.decode("utf-8").strip()
    raw_lines.append(line)
    if not line.startswith("data:"):
        continue
    data = line[5:].strip()
    if data == "[DONE]":
        break

    event = json.loads(data)
    event_count += 1
    if event.get("type") == "error":
        print(f"Error: {json.dumps(event.get('error', event))}", file=sys.stderr)
        failed = True
        break
    b64 = event.get("b64_json")
    size = f" ({len(b64)} chars)" if b64 else ""
    print(f"Event: {event.get('type')}{size}")

if event_count == 0 and raw_lines:
    # The server answered with a non-streamed JSON body instead of SSE
    result = json.loads("\n".join(raw_lines))
    for image in result.get("data", []):
        print(f"Generated image ({len(image.get('b64_json') or '')} chars)")

print(f"Stream finished after {event_count} event(s)")

if failed:
    sys.exit(1)

```

```typescript title="TypeScript (fetch)" expandable lines
const response = await fetch('https://openrouter.ai/api/v1/images', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    model: 'bytedance-seed/seedream-4.5',
    prompt: 'a detailed landscape painting',
    stream: true,
  }),
});

if (!response.ok) {
  throw new Error(`Request failed (${response.status}): ${await response.text()}`);
}

const reader = response.body!.getReader();
const decoder = new TextDecoder();
let buffer = '';
let raw = '';
let eventCount = 0;
let finished = false;

// Returns true when the stream should stop
function handleLine(line: string): boolean {
  const trimmed = line.trim();
  if (!trimmed.startsWith('data:')) return false;
  const data = trimmed.slice(5).trim();
  if (data === '[DONE]') return true;

  const event = JSON.parse(data);
  eventCount++;
  if (event.type === 'error') {
    console.error(`Error: ${JSON.stringify(event.error ?? event)}`);
    process.exitCode = 1;
    return true;
  }
  const size = event.b64_json ? ` (${event.b64_json.length} chars)` : '';
  console.log(`Event: ${event.type}${size}`);
  return false;
}

while (!finished) {
  const { done, value } = await reader.read();
  if (done) break;

  // SSE events can be split across network chunks, so buffer partial lines
  const chunk = decoder.decode(value, { stream: true });
  raw += chunk;
  buffer += chunk;
  const lines = buffer.split('\n');
  buffer = lines.pop() ?? '';

  for (const line of lines) {
    if (handleLine(line)) {
      finished = true;
      break;
    }
  }
}

// Process any final line that arrived without a trailing newline
if (!finished && buffer) handleLine(buffer);

if (eventCount === 0 && raw.trim()) {
  // The server answered with a non-streamed JSON body instead of SSE
  const result = JSON.parse(raw);
  for (const image of result.data ?? []) {
    console.log(`Generated image (${image.b64_json?.length ?? 0} chars)`);
  }
}

console.log(`Stream finished after ${eventCount} event(s)`);
```

```go title="Go" lines
package main

import (
	"bufio"
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"log"
	"net/http"

	"strings"

func main() {
	payload, _ := json.Marshal(map[string]any{
		"model":  "bytedance-seed/seedream-4.5",
		"prompt": "a detailed landscape painting",
		"stream": true,
	})

	req, err := http.NewRequest("POST", "https://openrouter.ai/api/v1/images", bytes.NewReader(payload))
	if err != nil {
		log.Fatal(err)
	}
	req.Header.Set("Authorization", "Bearer "+os.Getenv("OPENROUTER_API_KEY"))
	req.Header.Set("Content-Type", "application/json")

	res, err := http.DefaultClient.Do(req)
	if err != nil {
		log.Fatal(err)
	}
	defer res.Body.Close()

	if res.StatusCode < 200 || res.StatusCode >= 300 {
		body, _ := io.ReadAll(res.Body)
		log.Fatalf("Request failed (%d): %s", res.StatusCode, body)
	}

	// Models that do not stream return a single JSON body instead of SSE events
	if !strings.HasPrefix(res.Header.Get("Content-Type"), "text/event-stream") {
		var result struct {
			Data []struct {
				B64JSON string `json:"b64_json"`
			} `json:"data"`
		}
		if err := json.NewDecoder(res.Body).Decode(&result); err != nil {
			log.Fatal(err)
		}
		for _, image := range result.Data {
			fmt.Printf("Generated image (%d chars)\n", len(image.B64JSON))
		}
		return
	}

	// bufio.Reader handles arbitrarily long lines (base64 payloads can be megabytes)
	reader := bufio.NewReader(res.Body)
	eventCount := 0
	for {
		line, readErr := reader.ReadString('\n')
		trimmed := strings.TrimSpace(line)
		if strings.HasPrefix(trimmed, "data:") {
			data := strings.TrimSpace(strings.TrimPrefix(trimmed, "data:"))
			if data == "[DONE]" {
				break
			}

			var event struct {
				Type    string          `json:"type"`
				B64JSON string          `json:"b64_json"`
				Error   json.RawMessage `json:"error"`
			}
			if err := json.Unmarshal([]byte(data), &event); err != nil {
				log.Fatal(err)
			}
			eventCount++
			if event.Type == "error" {
				log.Fatalf("Error: %s", event.Error)
			}
			if event.B64JSON != "" {
				fmt.Printf("Event: %s (%d chars)\n", event.Type, len(event.B64JSON))
			} else {
				fmt.Printf("Event: %s\n", event.Type)
			}
		}

		if readErr == io.EOF {
			break
		} else if readErr != nil {
			log.Fatal(readErr)
		}
	}
	fmt.Printf("Stream finished after %d event(s)\n", eventCount)
}
```

## Billing and Cancellation

Image generation billing is **all-or-nothing**. A generation is either completed and billed in full, or it fails and is not billed &mdash; there is no partial or fractional image billing. This differs from chat completions, where a cancelled stream still bills for the tokens produced before cancellation.

- **Completed generations** are billed for the full image output based on the endpoint's pricing.
- **`response_format: "url"`**: a completed generation is billed once its output is stored, even if the client disconnects before the response arrives. The signed URL is only delivered in the response, so a client that never receives the response cannot retrieve the stored copy; storage is not a recovery mechanism for a lost response.
- **Failed or cancelled generations** are not billed. When a generation does not complete, the request returns a `502 Bad Gateway` rather than a partial result, and no charge is recorded.

If a client disconnects mid-generation, the upstream provider may still finish rendering the image and charge OpenRouter for it. Regardless, the client only ever observes one of two outcomes: a fully-billed result, or an error. Apart from the `response_format: "url"` case above, OpenRouter does not attempt to bill the user for work they did not receive.

For streaming requests, any partial preview images delivered before the stream ends do **not** create partial charges. Billing keys off completion of the final image, so a stream that terminates early (client disconnect or mid-stream error) is billed exactly as a failed generation: not at all.

### Handling 402 and 403 Billing Errors

Paid Image API requests are subject to your account credit balance, per-key credit limits, and the [in-flight spending budget](/api_reference/limits#in-flight-spending-budget), which holds an estimated cost while requests run and settle.

- **`402 Payment Required`** with `error.metadata.limit_source`:
  - `openrouter_in_flight_budget`: running and recently completed requests filled your in-flight spending budget. This is transient; wait for the `Retry-After` header and retry.
  - `openrouter_credits`: your account balance cannot cover the request (image authorization checks a minimum available balance before generation, so resizing will not clear a low-balance failure), or the single request's estimated cost exceeds your whole in-flight budget. Add credits to resolve a low-balance failure, or reduce image count/resolution when a single request exceeds the in-flight ceiling.
- **`403 Forbidden`** with `error.metadata.limit_source: "openrouter_key_limit"`: the API key's spending cap is exhausted, including when pending charges fill the cap. Raise the key limit or wait for its window to reset.

## Request Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `model` | string | Yes | Model slug (e.g. `bytedance-seed/seedream-4.5`) |
| `prompt` | string | Yes | Text description of the desired image |
| `n` | integer | No | Upper bound on images to generate (1-10); providers may return fewer, and single-image providers reject `n > 1` |
| `resolution` | string | No | Resolution tier (`512`, `768`, `1K`, `1.5K`, `2K`, `4K`) |
| `aspect_ratio` | string | No | Aspect ratio (`1:1`, `16:9`, `9:16`, `4:3`, `3:4`, `1:4`, `4:1`, etc.) |
| `size` | string | No | Convenience shorthand &mdash; a tier, or explicit pixels (`"2048x2048"`) where the provider accepts them (xAI and Sourceful V2/V2.5 reject pixel sizes with a 400; Sourceful V2.6 accepts them within its dimension limits) |
| `quality` | string | No | `auto`, `low`, `medium`, or `high` |
| `output_format` | string | No | `png`, `jpeg`, `webp`, `svg`, or `gif`. When omitted, the provider default applies. |
| `frame_count` | integer | No | Animation frames (2-64) for `gif` output; animation-capable models only, each with its own accepted range |
| `frame_duration_ms` | integer | No | Per-frame display time (20-2000 ms) for `gif` output |
| `markup` | object | No | Transparent PNG overlay (same shape as an `input_references` entry) guiding an edit; image-to-image only |
| `background` | string | No | `auto`, `transparent`, or `opaque` |
| `output_compression` | integer | No | Compression level (0-100) for webp/jpeg |
| `seed` | integer | No | Seed for deterministic generation (where supported) |
| `response_format` | string | No | `url` returns a signed [download URL](#response-format) that expires after 24 hours (recommended); `b64_json` (default when omitted) returns inline base64 bytes |
| `stream` | boolean | No | Stream partial images via SSE |
| `input_references` | array | No | Reference images for image-to-image generation |
| `user` | string | No | Stable identifier for your end-user; folded into a hashed upstream identity and never sent raw (see [User Tracking](/cookbook/administration/user-tracking)) |
| `session_id` | string | No | Unique identifier (max 256 characters) for grouping related requests in Broadcast and private logging; never sent to the provider. Overrides the `x-session-id` header if both are set. |
| `trace` | object | No | Observability and tracing metadata forwarded to configured Broadcast destinations. Named fields (`trace_id`, `trace_name`, `span_name`, `generation_name`, `parent_span_id`) are optional strings; custom keys may hold other JSON value types |
| `provider.only` | string[] | No | Allow only these provider slugs |
| `provider.order` | string[] | No | Try provider slugs in this order |
| `provider.ignore` | string[] | No | Exclude these provider slugs |
| `provider.sort` | string or object | No | Sort eligible endpoints by price, throughput, or latency |
| `provider.allow_fallbacks` | boolean | No | Allow another eligible provider when the primary fails |
| `provider.options` | object | No | Provider-specific parameters keyed by provider slug |

Use the [Image Models API](#via-the-image-models-api) to check which model-specific parameters each model and endpoint supports. Request-level fields such as `user`, `session_id`, `trace`, and `provider` are accepted independently of a model's `supported_parameters` list.
