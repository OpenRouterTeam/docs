Tool calls (also known as function calls) give an LLM access to external tools. The LLM does not call the tools directly. Instead, it suggests the tool to call. The user then calls the tool separately and provides the results back to the LLM. Finally, the LLM formats the response into an answer to the user's original question.

OpenRouter standardizes the tool calling interface across models and providers, making it easy to integrate external tools with any supported model.

**Supported Models**: You can find models that support tool calling by filtering on [openrouter.ai/models?supported_parameters=tools](https://openrouter.ai/models?supported_parameters=tools).

If you prefer to learn from a full end-to-end example, keep reading.

## Tool calling with the Agent SDK

The OpenRouter Agent SDK (`@openrouter/agent` for TypeScript, `openrouter_agent` for Python) runs the tool-calling loop for you. You define a tool with a name, description, input schema, and an `execute` function. When the model requests the tool, the SDK validates the arguments, runs your function, sends the result back to the model, and repeats until the model gives a final answer.

You don't need to append output items, match tool call IDs, or write your own agentic loop. The example below uses the same Project Gutenberg book search tool as the rest of this page.

<CodeGroup>

```typescript title="TypeScript" lines
import { OpenRouter } from '@openrouter/sdk';
import { callModel, tool } from '@openrouter/agent';
import { z } from 'zod';

const openRouter = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });

const searchGutenbergBooks = tool({
  name: 'searchGutenbergBooks',
  description:
    'Search for books in the Project Gutenberg library based on specified search terms',
  inputSchema: z.object({
    search_terms: z
      .array(z.string())
      .describe("List of search terms to find books in the Gutenberg library (e.g. ['dickens', 'great'] to search for books by Dickens with 'great' in the title)"),
  }),
  execute: async ({ search_terms }) => {
    const query = encodeURIComponent(search_terms.join(' '));
    const response = await fetch(`https://gutendex.com/books?search=${query}`);
    const data = (await response.json()) as {
      results: { id: number; title: string; authors: { name: string }[] }[];
    };
    return data.results.map((book) => ({
      id: book.id,
      title: book.title,
      authors: book.authors.map((author) => ({ name: author.name })),
    }));
  },
});

const result = callModel(openRouter, {
  model: 'google/gemini-3-flash-preview',
  instructions: 'You are a helpful assistant.',
  input: 'What are the titles of some James Joyce books?',
  tools: [searchGutenbergBooks] as const,
});

// The SDK runs the tool and sends the results back to the model
console.log(await result.getText());
```

```python title="Python" lines
import asyncio
import os

import httpx
from pydantic import BaseModel, Field
from openrouter_agent import OpenRouter, call_model, tool


class SearchInput(BaseModel):
    search_terms: list[str] = Field(
        description="List of search terms to find books in the Gutenberg library (e.g. ['dickens', 'great'] to search for books by Dickens with 'great' in the title)"
    )


class Author(BaseModel):
    name: str


class Book(BaseModel):
    id: int
    title: str
    authors: list[Author]


class SearchOutput(BaseModel):
    books: list[Book]


def search_gutenberg_books(params: SearchInput, ctx) -> SearchOutput:
    response = httpx.get(
        "https://gutendex.com/books",
        params={"search": " ".join(params.search_terms)},
        timeout=30,
    )
    data = response.json()
    return SearchOutput(
        books=[
            Book(
                id=book["id"],
                title=book["title"],
                authors=[Author(name=a["name"]) for a in book["authors"]],
            )
            for book in data["results"]
        ]
    )


async def main() -> None:
    client = OpenRouter(api_key=os.environ["OPENROUTER_API_KEY"])

    search_tool = tool(
        name="searchGutenbergBooks",
        description="Search for books in the Project Gutenberg library based on specified search terms",
        input_schema=SearchInput,
        output_schema=SearchOutput,
        execute=search_gutenberg_books,
    )

    result = call_model(
        client,
        {
            "model": "google/gemini-3-flash-preview",
            "instructions": "You are a helpful assistant.",
            "input": "What are the titles of some James Joyce books?",
            "tools": [search_tool],
        },
    )

    # The SDK runs the tool and sends the results back to the model
    print(await result.get_text())


asyncio.run(main())
```

```go title="Go" lines
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"log"
	"net/http"
	"net/url"
	"os"
	"strings"

func searchGutenbergBooks(searchTerms []string) any {
	resp, err := http.Get("https://gutendex.com/books?search=" + url.QueryEscape(strings.Join(searchTerms, " ")))
	if err != nil {
		return map[string]string{"error": err.Error()}
	}
	defer resp.Body.Close()
	var data struct {
		Results []struct {
			ID      int    `json:"id"`
			Title   string `json:"title"`
			Authors []struct {
				Name string `json:"name"`
			} `json:"authors"`
		} `json:"results"`
	}
	json.NewDecoder(resp.Body).Decode(&data)
	return data.Results
}

func main() {
	tools := []any{map[string]any{
		"type": "function",
		"function": map[string]any{
			"name":        "searchGutenbergBooks",
			"description": "Search for books in the Project Gutenberg library based on specified search terms",
			"parameters": map[string]any{
				"type": "object",
				"properties": map[string]any{
					"search_terms": map[string]any{
						"type":        "array",
						"items":       map[string]any{"type": "string"},
						"description": "List of search terms to find books in the Gutenberg library (e.g. ['dickens', 'great'] to search for books by Dickens with 'great' in the title)",
					},
				},
				"required": []string{"search_terms"},
			},
		},
	}}

	messages := []any{
		map[string]any{"role": "system", "content": "You are a helpful assistant."},
		map[string]any{"role": "user", "content": "What are the titles of some James Joyce books?"},
	}

	// Agentic loop: send tools, run requested tool calls, send results back
	for {
		body, _ := json.Marshal(map[string]any{
			"model":    "google/gemini-3-flash-preview",
			"messages": messages,
			"tools":    tools,
		})
		req, _ := http.NewRequest("POST", "https://openrouter.ai/api/v1/chat/completions", bytes.NewReader(body))
		req.Header.Set("Authorization", "Bearer "+os.Getenv("OPENROUTER_API_KEY"))
		req.Header.Set("Content-Type", "application/json")
		resp, err := http.DefaultClient.Do(req)
		if err != nil {
			log.Fatal(err)
		}
		raw, _ := io.ReadAll(resp.Body)
		resp.Body.Close()

		var out struct {
			Choices []struct {
				Message map[string]any `json:"message"`
			} `json:"choices"`
		}
		if err := json.Unmarshal(raw, &out); err != nil || len(out.Choices) == 0 {
			log.Fatalf("unexpected response (%d): %s", resp.StatusCode, raw)
		}
		msg := out.Choices[0].Message
		messages = append(messages, msg)

		calls, _ := msg["tool_calls"].([]any)
		if len(calls) == 0 {
			fmt.Println(msg["content"])
			return
		}
		for _, c := range calls {
			call := c.(map[string]any)
			fn := call["function"].(map[string]any)
			var args struct {
				SearchTerms []string `json:"search_terms"`
			}
			argStr, _ := fn["arguments"].(string)
			json.Unmarshal([]byte(argStr), &args)
			result, _ := json.Marshal(searchGutenbergBooks(args.SearchTerms))
			messages = append(messages, map[string]any{
				"role":         "tool",
				"tool_call_id": call["id"],
				"content":      string(result),
			})
		}
	}
}
```

```typescript title="TypeScript SDK" expandable lines
function convertOutputItemToInput(
  item: OpenResponsesResult['output'][number],
): InputsUnion1 {
  if (isOutputMessageItem(item)) {
    const content = item.content.filter(isKnownMessageContent);
    if (content.length !== item.content.length) {
      throw new Error('Received an unsupported message content type');
    }
    return { ...item, content };

    return item;
  }

  throw new Error(`Received an unexpected output item: ${item.type}`);
}

): item is OutputMessageItem {
  return item.type === 'message';

function isKnownMessageContent(
  content: OutputMessageItem['content'][number],
): content is OpenAIResponsesRefusalContent | ResponseOutputText {
  return content.type === 'output_text' || content.type === 'refusal';
}

function isFunctionCallOrReasoningItem(
  item: OpenResponsesResult['output'][number],
): item is OutputFunctionCallItem | OutputReasoningItem {
  return item.type === 'function_call' || item.type === 'reasoning';
}
```

#### Define the Tool

Next, we define the tool that we want to call. Remember, the tool is going to get _requested_ by the LLM, but the code we are writing here is ultimately responsible for executing the call and returning the results to the LLM.

<CodeGroup>

```typescript title="TypeScript SDK" expandable lines
type Book = {
  id: number;
  title: string;
  authors: { name: string }[];
};

async function searchGutenbergBooks(searchTerms: string[]): Promise<Book[]> {
  const searchQuery = searchTerms.join(' ');
  const url = 'https://gutendex.com/books';
  const response = await fetch(`${url}?search=${searchQuery}`);
  const data: unknown = await response.json();

  if (!isGutenbergResponse(data)) {
    throw new Error('Invalid response from the Gutenberg API');
  }

  return data.results.map((book) => ({
    id: book.id,
    title: book.title,
    authors: book.authors.map((author) => ({ name: author.name })),
  }));
}

const tools: ResponsesRequestToolFunction[] = [
  {
    type: 'function',
    name: 'searchGutenbergBooks',
    description:
      'Search for books in the Project Gutenberg library based on specified search terms',
    parameters: {
      type: 'object',
      properties: {
        search_terms: {
          type: 'array',
          items: {
            type: 'string',
          },
          description:
            "List of search terms to find books in the Gutenberg library (e.g. ['dickens', 'great'] to search for books by Dickens with 'great' in the title)",
        },
      },
      required: ['search_terms'],
    },
  },
];

function parseSearchTerms(argumentsJson: string): string[] {
  const args: unknown = JSON.parse(argumentsJson);

  if (
    !isRecord(args) ||
    !isStringArray(args.search_terms)
  ) {
    throw new Error('Invalid arguments for searchGutenbergBooks');
  }

  return args.search_terms;
}

function isGutenbergResponse(value: unknown): value is { results: Book[] } {
  return isRecord(value) && Array.isArray(value.results) && value.results.every(isBook);
}

function isBook(value: unknown): value is Book {
  return (
    isRecord(value) &&
    typeof value.id === 'number' &&
    typeof value.title === 'string' &&
    Array.isArray(value.authors) &&
    value.authors.every(isBookAuthor)
  );
}

function isBookAuthor(value: unknown): value is { name: string } {
  return isRecord(value) && typeof value.name === 'string';
}

function isStringArray(value: unknown): value is string[] {
  return Array.isArray(value) && value.every((item: unknown) => typeof item === 'string');
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}
```

```go title="Go" lines
type Book struct {
	ID      int    `json:"id"`
	Title   string `json:"title"`
	Authors []struct {
		Name string `json:"name"`
	} `json:"authors"`
}

func searchGutenbergBooks(searchTerms []string) ([]Book, error) {
	query := url.QueryEscape(strings.Join(searchTerms, " "))
	resp, err := http.Get("https://gutendex.com/books?search=" + query)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("Gutenberg search failed: %s", resp.Status)
	}
	var data struct {
		Results []Book `json:"results"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&data); err != nil {
		return nil, err
	}
	return data.Results, nil
}

// runSearch decodes a function call's arguments and runs the search. Invalid arguments
// and failed lookups go back to the model as an error, never as an empty result.
func runSearch(arguments string) string {
	var args struct {
		SearchTerms []string `json:"search_terms"`
	}
	var result any
	if err := json.Unmarshal([]byte(arguments), &args); err != nil {
```

### Interleaved Thinking

Interleaved thinking allows models to reason between tool calls, enabling more sophisticated decision-making after receiving tool results. This feature helps models chain multiple tool calls with reasoning steps in between and make nuanced decisions based on intermediate results.

**Important**: Interleaved thinking increases token usage and response latency. Consider your budget and performance requirements when enabling this feature.

#### How Interleaved Thinking Works

With interleaved thinking, the model can:

- Reason about the results of a tool call before deciding what to do next
- Chain multiple tool calls with reasoning steps in between
- Make more nuanced decisions based on intermediate results
- Provide transparent reasoning for its tool selection process

#### Example: Multi-Step Research with Reasoning

Here's an example showing how a model might use interleaved thinking to research a topic across multiple sources:

**Initial Request:**
```json expandable lines
{
  "model": "anthropic/claude-sonnet-4.5",
  "input": [
    {
      "role": "user",
      "content": "Research the environmental impact of electric vehicles and provide a comprehensive analysis."
    }
  ],
  "tools": [
    {
      "type": "function",
      "name": "search_academic_papers",
      "description": "Search for academic papers on a given topic",
      "parameters": {
        "type": "object",
        "properties": {
          "query": {"type": "string"},
          "field": {"type": "string"}
        },
        "required": ["query"]
      }
    },
    {
      "type": "function",
      "name": "get_latest_statistics",
      "description": "Get latest statistics on a topic",
      "parameters": {
        "type": "object",
        "properties": {
          "topic": {"type": "string"},
          "year": {"type": "integer"}
        },
        "required": ["topic"]
      }
    }
  ]
}
```

**Model's Reasoning and Tool Calls:**

1. **Initial Thinking**: "I need to research electric vehicle environmental impact. Let me start with academic papers to get peer-reviewed research."

2. **First Tool Call**: `search_academic_papers({"query": "electric vehicle lifecycle environmental impact", "field": "environmental science"})`

3. **After First Tool Result**: "The papers show mixed results on manufacturing impact. I need current statistics to complement this academic research."

4. **Second Tool Call**: `get_latest_statistics({"topic": "electric vehicle carbon footprint", "year": 2024})`

5. **After Second Tool Result**: "Now I have both academic research and current data. Let me search for manufacturing-specific studies to address the gaps I found."

6. **Third Tool Call**: `search_academic_papers({"query": "electric vehicle battery manufacturing environmental cost", "field": "materials science"})`

7. **Final Analysis**: Synthesizes all gathered information into a comprehensive response.

#### Best Practices for Interleaved Thinking

- **Clear Tool Descriptions**: Provide detailed descriptions so the model can reason about when to use each tool
- **Structured Parameters**: Use well-defined parameter schemas to help the model make precise tool calls
- **Context Preservation**: Maintain conversation context across multiple tool interactions
- **Error Handling**: Design tools to provide meaningful error messages that help the model adjust its approach

#### Implementation Considerations

When implementing interleaved thinking:

- Models may take longer to respond due to additional reasoning steps
- Token usage will be higher due to the reasoning process
- The quality of reasoning depends on the model's capabilities
- Some models may be better suited for this approach than others

### A Simple Agentic Loop

In the example above, the calls are made explicitly and sequentially. To handle a wide variety of user inputs and tool calls, you can use an agentic loop.

Here's an example of a simple agentic loop (using the same `tools`, `instructions`, and initial `input` as above):

<CodeGroup>

```typescript title="TypeScript SDK" expandable lines
async function callLLM(input: InputsUnion1[]): Promise<OpenResponsesResult> {
  const result = await openRouter.responses.send({
    responsesRequest: {
      model: MODEL,
      instructions,
      tools,
      input,
      stream: false,
    },
  });

  if (!('output' in result)) {
    throw new Error('Expected a non-streaming response');
  }
  if (result.status !== 'completed') {
    throw new Error(result.error?.message ?? `Response ended as ${result.status}`);
  }

  // Replay every output item in order so the model keeps its full context
  input.push(...result.output.map(convertOutputItemToInput));
  return result;
}

async function getToolResponse(toolCall: OutputFunctionCallItem): Promise<FunctionCallOutputItem> {
  if (toolCall.name !== 'searchGutenbergBooks') {
    throw new Error(`Unknown tool: ${toolCall.name}`);
  }

  const searchTerms = parseSearchTerms(toolCall.arguments);
  const toolResult = await searchGutenbergBooks(searchTerms);

  return {
    type: 'function_call_output',
    callId: toolCall.callId,
    output: JSON.stringify(toolResult),
  };
}

const maxIterations = 10;
let iterationCount = 0;
let finalText: string | undefined;

while (iterationCount < maxIterations) {
  iterationCount++;
  const response = await callLLM(input);
  const toolCalls = response.output.filter(
    (item): item is OutputFunctionCallItem => item.type === 'function_call',
  );

  if (toolCalls.length === 0) {
    const message = [...response.output].reverse().find((item) => item.type === 'message');
    finalText = message?.content.find((part) => part.type === 'output_text')?.text ?? '';
    break;
  }

  for (const toolCall of toolCalls) {
    input.push(await getToolResponse(toolCall));
  }
}

if (finalText === undefined) {
  console.warn("Warning: Maximum iterations reached");
}

console.log(finalText);
```

#### Streaming with Tool Calls

When using streaming responses with tool calls, handle the different content types appropriately. The Python, Go, and cURL tabs define the tool-call handler they use; `handleToolCalls` in the TypeScript tab is your own function with the same job:

<CodeGroup>

```typescript expandable lines
const stream = await fetch('https://openrouter.ai/api/v1/responses', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${OPENROUTER_API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    model: 'anthropic/claude-sonnet-4.5',
    input: input,
    tools: tools,
    stream: true
  })
});

if (!stream.body) {
  throw new Error('Expected a streaming response body');
}

const reader = stream.body.getReader();
const decoder = new TextDecoder();
let buffer = '';
const toolCalls = [];
const outputItems = [];

while (true) {
  const { done, value } = await reader.read();
  if (done) {
    break;
  }

  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop() ?? '';

  for (const line of lines) {
    if (!line.startsWith('data: ')) continue;
    const data = line.slice(6).trim();
    if (data === '[DONE]') continue;

    const event = JSON.parse(data);

    if (event.type === 'response.failed') {
      throw new Error(event.response.error?.message ?? 'Response failed');
    }
    if (event.type === 'response.incomplete') {
      throw new Error(
        `Response incomplete: ${event.response.incomplete_details?.reason ?? 'unknown reason'}`,
      );
    }
    if (event.type === 'response.output_text.delta') {
      console.log(event.delta);
    }

    if (event.type === 'response.output_item.done') {
      // Preserve every completed item in order. Reasoning and assistant items are
      // required context for some providers when sending tool results.
      outputItems.push(event.item);
      if (event.item.type === 'function_call') {
        // A completed function_call item carries the full arguments string.
        toolCalls.push(event.item);
      }
    }

    if (event.type === 'response.completed') {
      if (toolCalls.length > 0) {
        // Run each function_call locally, then send a follow-up request whose input
        // includes the original input, every output item, and a function_call_output
        // for each call (see the non-streaming loop above).
        await handleToolCalls(toolCalls, outputItems);
      }
      // Otherwise the regular response was printed from its output_text deltas above
    }
  }
}
```

```bash title="cURL" expandable lines
    result=$(search_gutenberg_books "$terms") || return 1
    follow_up=$(jq -c --arg call_id "$(jq -r '.call_id' <<<"$call")" --arg output "$result" \
      '. + [{type: "function_call_output", call_id: $call_id, output: $output}]' <<<"$follow_up")
  done < <(jq -c '.[]' <<<"$tool_calls")

  curl -sS https://openrouter.ai/api/v1/responses \
    -H "Authorization: Bearer $OPENROUTER_API_KEY" \
    -H "Content-Type: application/json" \

    jq -r '.output[] | select(.type == "message") | .content[] | select(.type == "output_text") | .text'
}

curl -sSN https://openrouter.ai/api/v1/responses \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --argjson input "$INPUT" --argjson tools "$TOOLS" \

while IFS= read -r line; do
  line=${line%$'\r'}
  [[ $line == "data: "* ]] || continue
  data=${line#data: }
  [[ $data == "[DONE]" ]] && continue

  case $(jq -r '.type' <<<"$data") in
    response.failed)
      jq -r '.response.error.message // "Response failed"' <<<"$data" >&2; exit 1 ;;
    response.incomplete)
      jq -r '"Response incomplete: " + (.response.incomplete_details.reason // "unknown reason")' <<<"$data" >&2; exit 1 ;;
    response.output_text.delta)
      jq -rj '.delta' <<<"$data" ;;
    response.output_item.done)
      # Preserve every completed item in order. Reasoning and assistant items are
      # required context for some providers when sending tool results.
      output_items=$(jq -c --argjson item "$(jq -c '.item' <<<"$data")" '. + [$item]' <<<"$output_items") ;;
    response.completed)
      echo
      # A completed function_call item carries the full arguments string.
      tool_calls=$(jq -c 'map(select(.type == "function_call"))' <<<"$output_items")
      if [[ $tool_calls != "[]" ]]; then
        # Run each function_call locally, then send a follow-up request whose input
        # includes the original input, every output item, and a function_call_output
        # for each call (see the non-streaming loop above).
        handle_tool_calls "$tool_calls" "$output_items"
      fi
      # Otherwise the regular response was printed from its output_text deltas above
      ;;
  esac
done
```

#### Tool Choice Configuration

Control tool usage with the `tool_choice` parameter:

```json lines
// Let model decide (default)
{ "tool_choice": "auto" }
```

```json lines
// Disable tool usage
{ "tool_choice": "none" }
```

```json lines
// Force specific tool (Responses API)
{
  "tool_choice": {
    "type": "function",
    "name": "search_database"
  }
}
```

```json lines
// Force specific tool (Chat Completions: the name is nested under `function`)
{
  "tool_choice": {
    "type": "function",
    "function": { "name": "search_database" }
  }
}
```

#### Parallel Tool Calls

Control whether multiple tools can be called simultaneously with the `parallel_tool_calls` parameter (default is true for most models):

```json lines
// Disable parallel tool calls - tools will be called sequentially
{ "parallel_tool_calls": false }
```

When `parallel_tool_calls` is `false`, the model will only request one tool call at a time instead of potentially multiple calls in parallel.

#### Multi-Tool Workflows

Design tools that work well together:

```json expandable lines
{
  "tools": [
    {
      "type": "function",
      "name": "search_products",
      "description": "Search for products in the catalog",
      "parameters": {
        "type": "object",
        "properties": {
          "query": { "type": "string", "description": "Product name or search terms" }
        },
        "required": ["query"],
        "additionalProperties": false
      }
    },
    {
      "type": "function",
      "name": "get_product_details",
      "description": "Get detailed information about a specific product",
      "parameters": {
        "type": "object",
        "properties": {
          "product_id": { "type": "string", "description": "Catalog product identifier" }
        },
        "required": ["product_id"],
        "additionalProperties": false
      }
    },
    {
      "type": "function",
      "name": "check_inventory",
      "description": "Check current inventory levels for a product",
      "parameters": {
        "type": "object",
        "properties": {
          "product_id": { "type": "string", "description": "Catalog product identifier" }
        },
        "required": ["product_id"],
        "additionalProperties": false
      }
    }

}
```

This allows the model to naturally chain operations: search → get details → check inventory.

#### Reliability Tracking

OpenRouter tracks how reliably each provider completes tool calls and surfaces this as the **Tool Call Error Rate** on the Performance tab of every model page. The same signal drives [Auto Exacto](/guides/routing/auto-exacto) provider ordering on tool-calling requests. For the exact validator, JSON Schema draft, regex semantics, and per-tool-call classification, see [How Tool-Calling Success Rate Is Measured](/guides/routing/auto-exacto#how-tool-calling-success-rate-is-measured).

For more details on the Responses API input format and tool parameters, see the [Responses API reference](/api_reference/responses/overview).
