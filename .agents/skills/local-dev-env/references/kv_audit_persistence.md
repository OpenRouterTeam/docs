# KV warmer audit persistence checks

The warmer (`api-kv-cron`, or `curl 'http://localhost:8794/__scheduled?cron=*/5+*+*+*+*'`) publishes the catalog to KV, then starts and awaits the audit inserts (`routing_fortuna_score_snapshots`, `routing_model_reference_stats`, `routing_tool_call_sort_snapshots`). HTTP 200 from `__scheduled` only confirms dispatch, so wait for the `warmKVModelsAndEndpoints completed` log and read `pending_write_count` and `pending_write_wait_duration` from it.

- Catalog seeding alone can produce Fortuna and tool-call snapshots while reference-stat rows stay empty. `buildRoutingHeuristics` requires both 5m and 30m perf data and `buildReferenceStatRows` needs non-null robust statistics, so seed recent local `endpoint_perf_minute_v4` aggregate states for at least four tool-capable endpoints of one variant across distinct providers, in the table's `quantilesState(...)(UInt32)` format. Inspect the current query filters before building fixtures, and tag and remove fixtures afterward.
- For a hung-insert test, hold `BEGIN; LOCK TABLE routing_fortuna_score_snapshots IN ACCESS EXCLUSIVE MODE;` in a dedicated local Postgres session and confirm the worker insert is waiting on `Lock/relation` in `pg_stat_activity`.
- Check `SHOW statement_timeout` first. The local database default is 8s, which yields `status:error` before the 15s client deadline. To reach the client-side timeout without changing worker code, temporarily set only the local database `statement_timeout='60s'` (fresh worker connections pick it up) and restore it afterward. The client timeout stops the wait, not the statement, so verify the warm completes while the lock is still held, then roll back the lock and let the late insert settle before taking recovery counts.
- Prove publication ordering with local Postgres `log_statement='mod'` insert timestamps against the KV put timestamps, and read `all` and `all_v2` from persisted Wrangler KV while the insert is still blocked. Matching fresh `routing_heuristics_snapshot_id` values prove they were published in that cycle. Restore the database logging setting afterward.
