# Curl-testing the Buddy API locally (cfw-internal only, no Tilt)

- cfw-internal runs standalone: `cd services/cfw-internal && INFISICAL_TOKEN=... bun run dev`. Under `OR_ENV=development` the bearer check in `buddyAuthMiddleware` is skipped, so no `Authorization` header is needed locally. Base URL `http://localhost:8794/api/v1/internal/buddy`.
- Use Infisical path `/services/cfw-internal-api`, not the directory name `/services/cfw-internal`; check `services/cfw-internal/package.json` (`x` script) for the current path before starting it.
- A fresh `openrouter-web_db` has zero providers/endpoints. Run `bun run db:migrate && bun run db:seed` first. The seed populates `users` with staff emails, so `X-Buddy-Actor-Email` for a real @openrouter.ai editor resolves to their clerk id in `last_edited_clerk_user_id` instead of Buddy's fallback id.
- Pick a field the route allowlists before asserting on a 200. `PATCH /provider/:slug` rejects `display_name` with 400 "No updateable fields provided". `description` (nullable) is a harmless field to flip and revert.
- The catalog-editor gate (`services/cfw-internal/src/routes/buddy-api/catalog-editor-gate.ts`) only fires on a top-level boolean `apply: true`. Without an allowlisted `X-Buddy-Actor-Email` (`packages/providers/configs/catalog-editors.ts`) it returns 403 before the route runs. Denials log `buddy_catalog_apply_forbidden` as a multi-line object in wrangler output, so grep with `-A4`.
- To exercise the bearer path (401 vs 403 ordering), run with `OR_ENV=staging` and distinct dummy `BUDDY_API_KEY` / `ADMIN_API_KEY` overrides: auth runs before the catalog gate, so a listed actor with the wrong key gets 401, not 403.
- If `infisical login` returns an empty token in a long-lived shell, run the login and the command together in one fresh shell.
- Under `OR_ENV=staging` the env middleware validates every dependency binding, not just the ones the route uses, so confirm an authenticated endpoint GET succeeds (not only `/health`) before asserting on route behavior. Keep DB/Hyperdrive URLs local and use inert placeholders for storage/analytics bindings.
- When cloning an endpoint row as a disposable fixture for `automation/capability-test` or `automation/baseline-unhide`, clone its `pricing_versions` row too. An endpoint without pricing fails the capability run with `Validator error: No usage available`.
- To exercise Buddy fallback attribution on `apply: true`, send an email that is listed in `catalog-editors.ts` but absent from local `users`. An unlisted email hits the 403 gate before attribution runs. Buddy's own clerk id (`BUDDY_CLERK_USER_ID`) must exist in local `users` if the editor foreign key is enforced.
- `model-author` routes need a `model_authors` row (`insert into model_authors (slug) values ('<slug>')` is enough, all other columns are nullable). `apply: true` writes `last_edited_clerk_user_id`, and `model_authors` enforces the `users` foreign key, so the resolved actor (or `BUDDY_CLERK_USER_ID` on fallback) must exist in local `users` or the write fails with a 500.
- Prove a write by comparing full endpoint row snapshots before and after (`updated_at`, the changed field, `last_edited_clerk_user_id`) alongside the route's `didUpdateEndpoint` flag. A preexisting Buddy editor value alone proves nothing, and snapshots make dry-run non-mutation checkable.
- Cleanup: delete only the disposable endpoint and pricing rows. Audit-history foreign keys keep inserted actor rows referenced, so leave those rather than disabling constraints.
