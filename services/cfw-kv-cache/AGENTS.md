# cfw-kv-cache

Lightweight Cloudflare Worker serving KV data via SWR (stale-while-revalidate) caching. Consumers access it through service bindings for consistently low-latency reads.

## Requirements

- **Avoid unnecessary redeploys.** Each deploy evicts all isolates, causing cold starts until the cache warms. The primary constraint is that changes in other workspace packages must not trigger a redeploy of this worker. Only redeploy when `services/cfw-kv-cache/` itself changes.
- **Minimize workspace dependencies.** Allowed runtime deps: `@openrouter-monorepo/cloudflare/kv-keys`, `@openrouter-monorepo/cloudflare/kv-cache-types`, `@openrouter-monorepo/cloudflare/live-config`, `@openrouter-monorepo/lib-result`, `@openrouter-monorepo/lib-zod`, `@openrouter-monorepo/lib-async/promise`, `@openrouter-monorepo/instrumentation/logger`, and `@openrouter-monorepo/instrumentation/statsd` (+ `cloudflare-statsd` for the `setStatsd` call in `index.ts`), plus `hono` (via `hono/tiny` and other subpath imports) for HTTP routing. Avoid heavy workspace packages (effect, db) — they increase the surface area for transitive changes that could trigger a redeploy. Use subpath imports only.
- **HTTP surface.** `GET /model-config?<attribute>=<value>` serves an unfiltered single model slice of `KV_ALL` (attributes mirror `findCachedModel`: `model`, `slug`, `permaslug`, `hf_slug`). `GET /kv/<key>` serves the raw JSON for a `ServableKvKey` (static `ValidKvKey`s plus regional `KV_ALL` variants like `all_europe`). Responses are cached by Workers Caching (`[cache]` in `wrangler.toml`) per their `Cache-Control` headers; error responses are `no-store`. Consumers invoke these routes through the service binding's `fetch()`, which participates in Workers Caching.
- **Per-entity private catalogs.** `GET /kv/private-endpoints/<entityId>` serves the raw JSON stored under `kvPrivateEndpointsKey(entityId)`. The prefix is deliberately not a `ServableKvKey`, so `/kv/<key>` never serves it. The handler goes through the shared SWR cache in `src/kv-handler.ts`, whose total cached bytes are bounded by `SWR_CACHE_MAX_BYTES` (oldest fills evicted first) so per-entity keys cannot grow it without limit, and whose freshness for `private_endpoints_*` keys is capped at `PRIVATE_ENDPOINTS_SWR_TTL_SECONDS` (30s), inside the route's `max-age`; repeat reads are also absorbed by Workers Cache. The entity id grammar and warm id cap live in `@openrouter-monorepo/cloudflare/kv-keys` (`PRIVATE_ENDPOINTS_ENTITY_ID_PATTERN`, `PRIVATE_ENDPOINTS_WARM_MAX_IDS`); the route prefix, warm cadence and derived `Cache-Control` live in `src/private-endpoints-contract.ts`; statuses, the authoritative-404 marker and the lookup metric are defined in `src/http-handlers/private-endpoints-handler.ts`.
- **Private catalog warmer.** A one-minute cron (`[triggers]` in `wrangler.toml`) asks the `PrivateEndpointsWarmer` Durable Object (named instance pinned with the `apac` location hint) to fetch `/kv/private-endpoints/<id>` through the `SELF` service binding, so that region's Workers Cache stays populated. The DO is stateless, the cron is the scheduler, and the route's `max-age` is two cron intervals so a missed tick still lands in the fresh window.
  - Targets come from `private_catalog.warm_entity_ids` in live config (`KV_LIVE_CONFIG` binding, read through `src/live-config.ts` on every tick).
  - The read never blocks on KV. A cold isolate serves the schema default and skips that tick while the first KV read runs in the background.
  - Ids that fail the entity id grammar are dropped with a count-only warning, only the first `PRIVATE_ENDPOINTS_WARM_MAX_IDS` distinct ids are warmed (the DO's per-call limit, also enforced by the live-config schema) with a count-only warning for the rest, an empty list makes the tick a no-op, and a live-config read failure logs and skips the tick.
- **Unpinned SWR reads:** Requests without a snapshot can serve any resident data immediately, including a versioned snapshot, while refreshing the legacy key in the background. A successful legacy refresh replaces the resident data without claiming a snapshot identity; failures retain it. TTL and jitter are configured via `[vars]` in `wrangler.toml`. Exact snapshot reads, including requests for older snapshots, do not use this fallback.
- **In-memory cache is intentional.** Per-isolate `Map` caching is acceptable here because the data is rarely-updated and request-independent, and its total size is bounded by `SWR_CACHE_MAX_BYTES`.
- **Use `wrap` for error handling**, not try/catch. Import from `@openrouter-monorepo/lib-result`.
- **Snapshot reads:** `cloudflare/catalog/snapshot-identity` is the shared, dependency-free key/identity contract. `lib-async/promise` supplies the bounded KV read without pulling in the higher-level catalog caches. Requests selecting a snapshot read only immutable keys, never the legacy key or the current-head marker; missing artifacts return a non-cacheable 503. Keep these subpath imports narrow.
