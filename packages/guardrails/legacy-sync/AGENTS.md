# Legacy management synchronization

Production legacy writers enter through `management.ts`, `key-assignments.ts`, or `member-assignments.ts`. The raw `packages/db` writer wrappers remain fixture primitives; do not add production callers. Transaction-taking DB helpers return bare promises, and orchestration owns rollback and Result handling. `packages/db` must never depend on this package.

Acquire the shared lifecycle advisory barrier for the owner, the actor, and every member subject, then the live account lock, before synchronization or mutation. Pass `assignedBy`, `last_edited_clerk_user_id`, and member IDs into `withGuardrailOwnerTransaction`; after the barriers are held it rejects a missing or deleted actor and a deleted member, while a historical member without a user row still relies on the membership FK. Account deletion/DSR acquire the exclusive barrier before user locks, so a writer that already holds its shared barriers finishes before cleanup and a later writer sees the deleted flag. Lock keys/members before their assignment rows; parent deletion does not always take the account lock. Sort multiple subjects. Workspace deletion and key moves use the same account serialization, and lock their actual workspaces. Re-read scanned source IDs inside the transaction. No helper creates a missing subject or workspace.

Source synchronization converts the complete persisted legacy record, reuses exactly equivalent same-owner/type policies, and changes mappings through copy-on-write. It does not enumerate assignments. Singular assignment synchronization is the bounded initialization API for migration. Explicit management assignment replaces all three types; initialization preserves independently changed or absent types after durable registration. Key-move repair relocates only matching provenance-owned choices and fails on destination conflicts.

Retained legacy rows alone own names, actors, and timestamps. Unassignment removes only still-owned choices through source cascades. Policy deletion, inheritance, and opt-out must not be interpreted as instructions to rematerialize a previously initialized type.

Use real Postgres integration tests for writer success, atomic rollback, source deletion, and lock ordering. Coordinate concurrent transactions with explicit promise barriers and observed database lock state. The deployment inventory and B5 handoff are in `OPERATIONS.md`.
