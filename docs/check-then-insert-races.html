Seven check-then-insert races become one atomic write each.

Seven write paths used to SELECT for an existing row and then INSERT or UPDATE based on what they saw. Two callers racing through the gap produced duplicate-key errors, duplicate rows, or a second startup credit grant. Each path now decides and writes in a single database step: either an INSERT ... ON CONFLICT DO NOTHING whose RETURNING row tells the caller whether it won, or a transaction that holds a pg_advisory_xact_lock around the read and the write.

Pattern Every table with a natural unique key (tags, model authors, workflow runs) uses ON CONFLICT. Every invariant the schema cannot express (a chart name visible to a user, one Google link per user, one startup grant per applicant) is serialized by a transaction-scoped advisory lock keyed on that invariant. Network calls (token exchange, HubSpot, Customer.io, Slack) stay outside every transaction.
01

Before and after: the shape of every fix

two write strategies
before

Read, decide, write

dbRead checks for an existing row. On a miss, dbWrite inserts. Two callers both miss and both insert.

Outcome under contention: unique-violation 500s (tags, model authors, workflow runs), duplicate rows (saved charts, Google links, PATs), or two promo redemptions for one applicant (startup grants).

after

Write once, read the outcome

Natural unique key: insertInto(...).onConflict(oc => oc.columns([...]).doNothing()).returning(...). A missing RETURNING row means a concurrent caller won, so the caller re-reads from the primary.

No schema key: db.transaction() that runs SELECT pg_advisory_xact_lock(hashtext(key)), then the visibility check, then the write. The lock releases on commit.

The ON CONFLICT path

tags · model authors · workflow runs
// packages/db/tags/queries.ts
const insertResult = await dbWrite('db.getOrCreateTags.insert', (q) => q.insertInto('tags').values(tagsToCreate)
  .onConflict((oc) => oc.columns(['name', 'tagger_name']).doNothing())
  .returning(['id', 'name', 'tagger_name', 'category']).execute());
const insertedNames = new Set(insertResult.data.map((t) => t.name));
const racedNames = tagsToCreate.map((t) => t.name).filter((name) => !insertedNames.has(name));
// raced names were inserted by a concurrent caller: re-read them from the primary
const racedResult = await dbRead('db.getOrCreateTags.raced', { primaryOnly: true }, (q) => selectTags(q, { names: racedNames, taggerName }));

// packages/synapse-corpus/workflows/dispatch.ts

  .onConflict((oc) => oc.columns(['corpus_id', 'definition_id', 'trigger_event_id']).doNothing())
  .returning('id').executeTakeFirst();
