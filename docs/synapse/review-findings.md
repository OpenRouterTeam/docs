# Synapse Corpus — Review Findings Register

**Status:** disposition record for the adversarial review of [#32290](https://github.com/OpenRouterTeam/openrouter-web/pull/32290)
**Date:** 2026-08-06

A multi-lens adversarial review (schema/data, security/privacy, infrastructure, scope/pragmatism, retrieval quality, doc consistency — each finding independently verified against the docs and the in-flight stack PRs) produced 19 confirmed findings. This register maps each to its resolution so nothing is silently dropped and downstream PR reviews can check amendments against it. Refuted findings are listed at the end because they are the objections most likely to resurface.

## Refuted findings (kept for calibration)

These were raised and did **not** survive adversarial verification. They are recorded because they are the most likely objections to recur in PR review.

| Objection | Why it does not hold |
|---|---|
| "No walking skeleton — all foundation before any end-to-end value" | MCP search lands mid-stack (layer 8); entity resolution and synthesis are correctly deferred behind the query surfaces. The foundation layers are the minimum for a *private-data* system: ACLs and deletion cannot be retrofitted. |
| "Hyperdrive on the retrieval path contradicts the monorepo's Hyperdrive warning" | The infra RFC scopes Hyperdrive to interactive Worker traffic only; bulk/index work runs in Cloud Run with direct Cloud SQL connections. The monorepo warning targets hot *inference* paths, which the corpus never touches. |
| "The ripgrep/clone service is unspecified" | Clone/cache hosting is an explicitly-named blocking decision (D13 context); the bulk Cloud Run service owns checkouts — architecture §8, §12. |
| "The dedicated-instance recommendation contradicts the architecture doc" | True pre-review (F16); resolved by D1 and the infra RFC, which supersedes the earlier graduated default. |
| "RRF double-counting lets multi-representation objects flood the candidates" | Post-fusion representation-aware per-object caps collapse a thread's distillation/bursts/chunks to the object before caps apply — architecture §9 step 6. |
| "Gates were violated because all PRs exist before the first gate approval" | Gates are merge conditions, not authoring permissions; the stacked topology mechanically enforces order, and nothing has merged. The manifest now states this explicitly (§7). |
| "Cloud Run can't consume Cloudflare Queues / bind R2" | The bulk worker consumes the same envelope contract, not CF Queue bindings; R2 access is via S3-compatible API. Boundaries are in the infra RFC. |
