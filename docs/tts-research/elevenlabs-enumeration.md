# ElevenLabs TTS adapter: local enumerative E2E results

Evidence for [#46797](https://github.com/OpenRouterTeam/openrouter-web/pull/46797). Companion to `elevenlabs.md` (provider research). This file records what the adapter on that branch did for every request shape the matrix below sends, so each row can be cross-checked against the ElevenLabs dashboard (History and request logs) by `el_request_id` and `el_history_item_id`, and against local OpenRouter records by `generation_id`.

## Provenance

- Run date: 2026-09-25 (UTC) for groups A to L, 2026-09-26 for group M (BYOK). Adapter revision under test: branch `devin/1790313366-elevenlabs-tts-adapter` at the commit that adds this file, plus the fixes that the run itself produced (listed under Adapter changes).
- Path: local `cfw-tts-api` worker (port 8791) with the seven ElevenLabs endpoints staged in local Postgres and the KV catalog, managed key from dev Infisical (`/services/cfw-tts-api`, `ELEVENLABS_API_KEY`, Enterprise tier). Upstream traffic went through a local logging proxy so the exact upstream path, query, status, and response headers are recorded per row. Group M (BYOK) was added on 2026-09-26: the same dev key was registered as an encrypted ElevenLabs BYOK key on the local test user (`provider_api_keys`, deleted after the run), so the rows show the BYOK path end to end (`is_byok=true` on the generation, usage 0, the caller's ElevenLabs account billed the `character-cost`). The two BYOK-only formats are therefore covered on both the managed-key rejection side (B rows) and the BYOK acceptance side (M rows).
- Audio verification: every 200 body was written to disk and probed with `ffprobe` (codec, sample rate, channels, bitrate, duration). PCM rows are probed as signed 16-bit little-endian mono at the rate the adapter advertised in `Content-Type`.
- Redaction: no API keys, no audio bytes, no base64. Inputs are shown bounded with their code-point and UTF-16 counts, `[Ncp/Mu16]`. Upstream error bodies are summarised, never quoted in full.
- Dashboard verification not performed from this session: the dev key lacks the `user_read` and `history_read` scopes, so the IDs are recorded for a human with dashboard access to spot-check.
- Classification legend: `Expected` matched the pre-run expectation. `Observed (no fixed expectation)` was run to learn the behaviour. `Observed (as expected, noted)` matched and carries a note worth keeping. `Deviation: adapter changed` produced a fix on this branch with a raw fixture and a regression test. `Deviation: provider behaviour` documents ElevenLabs behaviour that differs from its docs, no adapter change. `Deviation: shared platform behaviour` is outside the adapter and flagged for follow-up.

## Adapter changes made from this run

| Case | What the run showed | Change on this branch | Evidence |
|---|---|---|---|
| H-voice-unicode, H-voice-query-injection | Non-ID-shaped voice strings get HTTP 400 `invalid_uid` from ElevenLabs | Map `400:invalid_uid` to the sanitized `Unknown voice` 400 for anything that still reaches ElevenLabs, and reject non-ASCII voices locally (see H-voice-traversal) | `fixtures/error-400-invalid-voice-id.response.json` plus test |
| H-voice-traversal, H-voice-lone-surrogate | `../` in the voice is percent-encoded into the path and ElevenLabs answers 404 with bare-string `detail: "Not Found"` (no `status`). A lone UTF-16 surrogate made `encodeURIComponent` throw, surfaced as HTTP 502 | Reject any voice outside `[A-Za-z0-9_-]` with a 400 before dispatch, so the voice can never reshape the request path. The bare-string 404 is left to the shared handler as an upstream fault because the same body is what a misconfigured base URL produces (review finding after the run, replacing an earlier `Unknown voice` mapping of that shape) | `fixtures/error-404-unrouted-voice-path.response.json` plus tests |
| G-over-limit-codepoints-v3 | 5000 emoji pass the code-point length check, ElevenLabs strips emoji and rejects `input_text_empty` | Map `400:input_text_empty` to a bounded message | `fixtures/error-400-empty-text.response.json` plus test |
| E-langnorm-string | ElevenLabs coerces `"yes"` to `true` then rejects `language_text_normalization_not_supported` | Map to a bounded 400 | `fixtures/error-400-language-normalization.response.json` plus test |
| G-input-space | ElevenLabs charges `character-cost: 1` for whitespace-only input | Bill a one-character floor for whitespace-only input | test |
| C-speed-passthrough-only | Canonical `speed` defaults to 1 in the request schema, so a caller-supplied `voice_settings.speed` was silently overwritten with 1 whenever canonical `speed` was omitted (row ran at speed 1, not 0.8) | Only a non-default canonical `speed` overrides `voice_settings.speed`; at the default the passthrough value is forwarded as-is (review finding after the run) | test |

## Provider observations (ElevenLabs behaviour that differs from its docs)

| Case | Observation |
|---|---|
| E-seed-neg, E-seed-over | `seed` of -1 and 4294967296 are accepted (docs: 0 to 4294967295) |
| E-seed-repeat-a, E-seed-repeat-b | Same seed twice gives identical byte count and metadata but different bytes. Seed is best effort |
| D-vs-v3-stability-0.3 | Continuous `stability` accepted on `eleven_v3` (docs list 0, 0.5, 1) |
| D-vs-boost-string | String `"true"` for `use_speaker_boost` is coerced, no 422 |
| G-input-empty | `eleven_multilingual_v2` accepts empty text and charges 1 character. `eleven_v3` rejects it with `input_text_empty` |
| E-norm-on-flash25 | `apply_text_normalization: "on"` accepted on `eleven_flash_v2_5` with the Enterprise key (docs: Enterprise only) |
| H-voice-name | A display name is treated as an ID and gets 404 `voice_not_found`. Names are not resolved |
| L-burst-0 to L-burst-7 | 8 parallel requests all 200, `current-concurrent-requests` peaked at 8. The Enterprise ceiling was not reached |
